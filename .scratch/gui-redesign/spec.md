# 图形界面重做：设计规格

Status: ready-for-agent

对象是 `Sources/GUI/`（AppKit）。命令行和 `Sources/Core/` 的行为不变。
可视化参照：[`mockup.html`](mockup.html)（浏览器打开，A–D 四张）。草图只定排版、层级和文案；
真实界面一律用 AppKit 的系统控件、系统色、系统字体，草图里的色值只是系统色的近似，不要照抄。

## 1. 这个界面是给谁、干什么的

一个人把自己的照片从 JPEG 换成 HEIF，最怕的是拍摄时间、位置、备注在转换里悄悄丢了。
所以界面的头等大事不是「转完了」，而是**每一张带过去了什么、差了什么，一眼看得见**。
其余一切从简，像访达的列表视图那样安静。

设计上只有一处用力：右栏的「结果」——选中一张看它的校验结论和每一处差异，不选时看这一批的
汇总。别处不加装饰。

## 2. 约束

- AppKit，纯代码（没有 xib、没有资源目录），`swiftc` + Command Line Tools 能编；零第三方依赖。
  系统框架可以用。
- `Model.swift` 继续不依赖任何 UI 框架，逻辑放在那里并由 `Tests/guimodel` 测；视图只做呈现。
- 中文界面。浅色、深色、「增强对比度」都要对——所以颜色只用语义色（`labelColor`、
  `secondaryLabelColor`、`separatorColor`、`controlAccentColor`、`systemGreen/Orange/Red` 等），
  不写死色值；跟随用户的系统强调色。
- 字体用系统字体（`NSFont.systemFont`），数字列用 `monospacedDigitSystemFont`，不用等宽字体。
- 图标用 SF Symbols（`NSImage(systemSymbolName:)`），不用 emoji、不画位图。

## 3. 窗口结构

默认 980×640，最小 860×520。统一样式的工具栏（`NSToolbar`，`.unified`）。

```
┌────────────────────────────────────────────────────────────────┐
│ ● ● ●  JPEG 转 HEIF                              ＋ 添加  清空 │ 工具栏；副标题「8 张照片」
├──────────────────────────────────────────────┬─────────────────┤
│ 名称              大小        节省   校验 ▾  │ [ 设置 | 结果 ] │
│ ▢ IMG_2020….jpg  1.9 MB → 737 KB  62%  ⚠ 5 处差异 │                 │
│ ▢ IMG_2026….jpg  3.3 MB → 989 KB  71%  ⚠ 2 处差异 │   右栏 300pt    │
│ ▢ 损坏的文件.jpg   12 KB              ⊗ 失败   │   （见第 5、6 节）│
│ ▢ IMG_2022….jpg  75 KB → 31 KB   59%  ✓ 无差异 │                 │
│   …                                          │                 │
├──────────────────────────────────────────────┴─────────────────┤
│ 转完 7 张，省下 14.8 MB。3 张有差异，1 张失败。    [ 开始转换 ] │ 底栏 48pt
└────────────────────────────────────────────────────────────────┘
```

- 左边是列表，占满剩余宽度；右栏固定 300pt，左边一条分隔线；底栏通栏。
- 整个窗口都接受拖放（不只是列表），拖进来时列表区描一圈强调色的边。
- 窗口大小和位置记住（现有的 `setFrameAutosaveName` 保留）。

## 4. 列表

`NSTableView`，有表头、交替行底色、行高 48、可多选。四列：

| 列 | 内容 | 对齐 | 宽度 |
|---|---|---|---|
| 名称 | 34×34 缩略图（圆角 5）+ 文件名 + 第二行小字 | 左 | 弹性，最小 220 |
| 大小 | 转完：`1.9 MB → 737 KB`（前半次要色，后半正文色）；没转：只有源的大小 | 右 | 168 |
| 节省 | `62%`；变大了写 `大 33%`（中等字重） | 右 | 64 |
| 校验 | 图标 + 文字，见下表 | 左 | 112 |

- 文件名**中间截断**（`.byTruncatingMiddle`），任何宽度下都不许压到别的列。
- 第二行小字：有子目录/来源文件夹时显示它（沿用 `subpath` 的规则）；跳过、失败时显示原因；
  其余情况为空（不再堆「元数据 N 项 · 扩展属性 N 项」，那些挪到右栏）。
- 缩略图：后台用 ImageIO 生成（最长边 96 像素，缓存），没出来之前用系统的 JPEG 文件图标。
  源文件被删掉以后改从 HEIF 取。
- 点表头排序（四列都能排）。「校验」列的顺序：失败 → 有差异（多的在前）→ 未校验 → 无差异 →
  转换中 → 等待。默认按加入的顺序。
- 状态一律**图标带颜色、文字不带**（颜色不是唯一的信息载体，文字对比度也不靠彩色字）：

| 状态 | 图标（SF Symbol） | 图标色 | 文字 | 文字样式 |
|---|---|---|---|---|
| 等待 | 无 | — | 等待 | 三级色 |
| 转换中 | 小号转圈（`NSProgressIndicator` spinning, small） | — | 转换中 | 次要色 |
| 无差异 | `checkmark.circle.fill` | systemGreen | 无差异 | 次要色 |
| 有差异 | `exclamationmark.triangle.fill` | systemOrange | N 处差异 | 正文色、中等字重 |
| 未校验 | `minus.circle` | 次要色 | 未校验 | 次要色 |
| 已跳过 | `arrow.uturn.right.circle` | 次要色 | 已跳过 | 次要色 |
| 失败 | `xmark.circle.fill` | systemRed | 失败 | 正文色、中等字重 |

  正常的要安静，例外的才显眼：一批几百张里绝大多数是「无差异」，它们不该抢眼。
- 选中一行：右栏切到「结果」并显示这一张。点空白处取消选中。
- 双击一行：在访达里显示产物（没转完就显示源文件）。
- 右键菜单：在访达中显示源文件 / 在访达中显示 HEIF（有产物才有）/ 拷贝差异（有差异才有）/
  从列表中移除（转换中不可用）。
- 空列表时这一块换成第 7 节的空状态。

## 5. 右栏「设置」

顶上一个两段的分段控件 `设置 | 结果`。还没有任何结果时「结果」不可点。
转换进行中「设置」里的控件全部禁用。

分组，每组一个小标题（11pt、次要色、半粗），组间一条分隔线。带说明的选项，说明用 11pt 次要色
写在选项下面，最多两行：

**画质**
- 滑杆 + 数值（现有的取值范围和提示语保留，如「日常存档的推荐区间」）。

**保存到**
- 弹出按钮：`源文件旁边` / `指定文件夹…`。选了文件夹，下面一行显示路径（中间截断，
  点它重新选）。
- ☐ 包含子文件夹
- ☐ 覆盖同名的 HEIF

**元数据**
- ☑ 转完逐项校验
  说明：比对拍摄时间、位置、备注和扩展属性，列出丢失或变化的每一项
- ☐ 把「照片」里的说明写进文件
  说明：说明原本存在文件之外，离开这台 Mac 容易丢
  （对应 `ConversionOptions.embedCaption`）

**源文件**
- ☐ 校验无差异后删除源文件
  说明：有差异的、HEIF 反而更大的，源文件都留着
  勾上它会自动勾上并锁住「转完逐项校验」（现有逻辑）。标签不用红字。

**高级**（折叠，默认收起，记住展开状态）
- ☐ EXIF 交给系统重写
  说明：默认把源文件的 EXIF 原样搬过去。个别软件读不了这样的文件时再勾
  （对应 `ConversionOptions.rawExif = false`）

记住上次的设置（`UserDefaults`）：画质、保存到、包含子文件夹、逐项校验、写入说明、高级里的那一项、
「高级」是否展开。**「删除源文件」和「覆盖同名的 HEIF」不记**，每次启动都是关的。

## 6. 右栏「结果」

### 6.1 选中了一张

从上到下：

1. 预览图：宽度撑满，高 132，等比裁切居中，圆角 7。下面文件名（15pt 半粗，中间截断）和所在
   文件夹（11pt 次要色，`~` 缩写，点它在访达中显示）。
2. **结论**——这一栏的标题，15pt 半粗，前面带状态图标：
   - `无差异`，下面一行小字 `逐项校验过，没有丢失或变化。`
   - `N 处差异`，下面一行小字说明源文件的去向：`源文件还在，没有删除。` 或（没开删除时）不写。
   - `未校验`，小字 `这次转换没有开「转完逐项校验」。`
   - `失败` / `已跳过`，小字是原因。
   - 等待、转换中：`等待转换` / `正在转换…`，下面的内容都不显示。
3. 差异列表（有差异才有）：每条一行，前面一个小标记，后面是正文，可以选中复制，自动折行：
   - 以 `丢失 ` 开头的 → 标记 `丢失`（systemRed），正文去掉这两个字；
   - 以 `变化 ` 开头的 → 标记 `变化`（systemOrange），正文去掉这两个字；
   - 其它 → 标记 `注意`（次要色），正文是整行。
   列表下面一个小按钮 `拷贝全部`。
4. 明细（标签在左、值在右的两列，标签次要色）：
   - 体积：`3.3 MB → 989 KB`，下一行 `省 71%` 或 `比源文件大 33%`
   - EXIF：`与源文件逐字节相同` + 下一行字节数；改写过备注的 `原样搬过去，备注改成了系统读得出的写法`；
     保留了 EXIF 原值的照 `RawExifOutcome` 的说明写；没照搬的 `由系统重写` + 下一行原因。
     取自 `ConversionReport.rawExif`，文字直接复用它已有的描述，不要另编一套。
   - 元数据：`N 项`
   - 扩展属性：`N 项`
   - 说明（开了写入说明才有）：取自 `ConversionReport.caption` 的描述
   - 重编（重编过才有）：取自 `ConversionReport.reencode` 的描述
5. 备注（`ConversionReport.note` 非空才有）：原文照显。

### 6.2 没选中任何一行（转完或转到一半）

这一批的汇总：

1. 标题：`转完 7 张，省下 14.8 MB`（还在转时 `已转 3 张，共 8 张`），下一行 `22.6 MB → 7.8 MB`。
   产物总体比源大时写 `转完 7 张，多占 1.2 MB`。
2. 分类计数，一行一类，零的不显示：校验无差异 / 有差异 / 未校验 / 已跳过 / 失败 / HEIF 比源文件大。
   点一类：列表按「校验」排序并选中该类的第一张。
3. `最常见的差异`（有差异才有）：把所有差异行归并后按张数从多到少列前 5 条。归并规则（纯函数，
   放 `Model.swift`）：取每行到第一个 ` = `、`: `、`：` 为止的部分，再把连续的数字换成 `N`；
   同一张图里归并后相同的只算一次。
4. 开了删除源文件时加一行：`删了 4 张源文件，留下 3 张`。

多选时按 6.2 显示，但只统计选中的那些，标题改成 `选中 3 张`。

## 7. 空状态

列表区居中：一个 `photo.on.rectangle.angled` 图标（46pt，三级色）、标题
`把 JPEG 或文件夹拖进来`（17pt 半粗）、一段说明
`转成 HEIF 更省空间。拍摄时间、位置、备注原样带过去，转完逐项校验给你看。`（次要色，最宽 380）、
一个按钮 `选择文件或文件夹…`。不画虚线框。右栏照常显示「设置」。

## 8. 底栏

左边一句话，右边主按钮。

| 情形 | 左边 | 右边 |
|---|---|---|
| 没有照片 | `还没有照片` | `开始转换`（禁用） |
| 有待转的 | `8 张，共 22.6 MB` | `开始转换`（强调色，回车触发） |
| 转换中 | `已转 3 张，共 8 张` + 一条 180pt 的进度条 | `取消` |
| 转完 | `转完 7 张，省下 14.8 MB。3 张有差异，1 张失败。`（没有的类不写） | `开始转换`（没有待转的就禁用） |
| 取消了 | `已取消。转完 3 张，还有 5 张没转。` | `开始转换`（继续转剩下的） |

现有 `model.warning`（例如没选输出文件夹）出现时，显示在这句话的位置，前面一个橙色三角图标。

## 9. 确认与提示

- 勾着「删除源文件」点开始：弹出窗口内的确认（sheet）。标题 `转完后删除源文件？`，正文
  `只删逐项校验无差异、而且 HEIF 没有变大的那些。删除后不进废纸篓。`，按钮 `删除源文件并转换`
  （破坏性样式）和 `取消`（默认）。（「不进废纸篓」以现有实现为准；如果现在是移到废纸篓，按实际写。）
- 转完时应用不在前台：`NSApp.requestUserAttention(.informationalRequest)`。不发通知。

## 10. 菜单与键盘

菜单栏在现有的基础上加：

- 文件：`添加…` ⌘O；`在访达中显示` ⇧⌘R；`从列表中移除` ⌘⌫；`清空列表`
- 转换：`开始转换` ⌘↩；`取消` ⌘.
- 编辑：`拷贝`在列表有选中时拷贝选中各行的「文件名 + 差异」；`全选` ⌘A 选中全部行
- 显示：`设置` ⌘1；`结果` ⌘2

列表可以用方向键移动、空格不做事；Tab 能走到右栏每个控件；主按钮是默认按钮。菜单项按状态
启用/禁用（`validateMenuItem`）。

## 11. 无障碍

- 每一行有一句完整的无障碍描述：`IMG_2026.jpg，3.3 MB 转成 989 KB，省 71%，2 处差异`。
- 状态图标设 `accessibilityLabel`（或标记为装饰，由行的描述覆盖）；纯图标按钮都有标签。
- 「减弱动态效果」打开时不做任何过渡动画。本设计本来也只有两处动画：行状态变化时图标淡入
  （150ms）、拖入时描边出现。
- 颜色之外总有文字或图标形状区分状态（第 4 节的表）。

## 12. 模型要补的

`FileRow` 现在没有带上 `rawExif`、`reencode`、`caption`；补上，并提供第 6 节要用的纯函数：

- 差异行分成（标记，正文）；
- 「最常见的差异」的归并与计数；
- 汇总的各类计数、总体积、删了几张源文件；
- 排序键（第 4 节的校验列顺序）；
- 一行的无障碍描述；
- 底栏那句话（第 8 节的每一种情形）。

设置的读写（`UserDefaults`）放在一个可以注入存储的小类型里，好测「删除源文件不被记住」。

## 13. 验收

1. `make test` 全绿；`Tests/guimodel` 为第 12 节的每个函数加用例（含边界：0 张、全失败、
   全无差异、产物总体变大、取消后继续、多个来源文件夹同名文件）；设置持久化的用例。
   三个计数同步（现为 587 / 727 / 48，以你开工时 `Tests/selftest.sh` 里的为准）。
2. 现有的界面端到端断言（`Tests/uisnapshot … --convert` 那几条）继续通过。
3. `Tests/uisnapshot` 扩展出下面这些参数，并生成一组截图供交接方看（放在你自己的临时目录，
   报告里给出路径）：
   - `--appearance light|dark`、`--size 宽x高`、`--tab settings|result`、`--select <文件名>`、
     `--sort verify`、`--state empty|queued|done`
   - 要交的截图：空状态（浅）、排队中（浅，设置）、转完选中一张有差异的（浅、深各一）、
     转完选中一张无差异的（浅）、转完不选中（浅、深各一）、最小窗口尺寸下转完选中一张（浅）、
     文件名很长的一行（浅）。
   样本用 `Tests/fixture` 和 `Tests/mangle` 造，要有无差异、有差异、失败、比源文件大四种。
4. 自查清单（逐条在报告里回答是/否）：
   - 任何窗口宽度下文件名都不压到「大小」列；
   - 深色下所有文字可读，没有写死的颜色；
   - 状态文字没有用彩色字；
   - 没有 emoji、没有虚线框、没有胶囊形的彩色标签；
   - 「删除源文件」「覆盖同名的 HEIF」重启后是关的；
   - 转换中「设置」不可改，转完可改；
   - 键盘能完成：添加、开始、取消、在列表里移动、切换右栏。
5. README 的「图形界面」一节按新界面改写（只写现在的行为）。

## 14. 不做的

- 不做偏好设置窗口、不做多窗口、不做 Quick Look 预览、不发系统通知。
- 不做筛选条（按「校验」列排序和汇总里的分类计数已经够用）。
- 不换成 SwiftUI。
