## 1. 要什么

JPEG 转成 HEIF 后，自动判断画质有没有明显下降；明显下降的，按设置**要么不转（保留 JPEG、不留
产物）**，**要么先用更高的质量重编一次再判**，仍不达标才不转。判据的两个门槛和这两种处理方式，
都要能在设置里选（界面）和用参数指定（命令行）。默认开。

只管 JPEG。RAW（raw2heif、界面里混在一批的 RAW）这一轮不做画质核对。

## 2. 交接方量到的事实（main = a3ba767，本机 M5 Pro）

量具是交接方临时写的：两边用 ImageIO 解码，画进 sRGB 8 位 RGBA，算下面 §3.1 的两个数。

| 样本 | 质量 | PSNR 最低 / 中位 | 最差 1% 局部 SSIM 最低 / 中位 |
|---|---|---|---|
| 用户的风景照 180 张（三个相机/手机来源，最大 6000×4000） | 0.8 | 37.6 / 43.8 dB | 0.961 / 0.980 |
| 用户测试集 10 张（相机照片、截图、网图、HDR） | 0.8 | 37.6 / 约 44 dB | 0.967 / — |
| 同一批风景照抽 36 张 | 0.6 | 34.3 / 42.1 | 0.933 / 0.968，低于 0.90 的 0 张 |
| 同上 | 0.5 | 32.8 / 41.0 | 0.910 / 0.951，低于 0.90 的 0 张 |
| 同上 | 0.4 | 31.8 / 39.9 | 0.862 / 0.923，**低于 0.90 的 9 张** |

合成的难图（CoreGraphics 画好存成 JPEG 质量 0.95，再按 0.8 转）：

| 合成图 | PSNR | 最差 1% 局部 SSIM |
|---|---|---|
| 白底小字（1170×2532 聊天截图样） | 43.9 | 0.9985 |
| 彩底彩字 | 39.3 | 0.972（质量 0.4 时 0.850） |
| 1 像素细条纹 | 54.2 | 1.000 |
| 平滑渐变 | 60.5 | 0.997 |
| 本来就压得很狠的小图（质量 0.3 存的） | 35.0 | 0.968（且产物比原图大，现有规则已拦） |

结论：默认质量 0.8 下没有一张明显下降；PSNR 对质量变化不敏感，最差 1% 局部 SSIM 敏感。这个核对
是安全网（编码器偶发异常、界面把质量拉到 0.4–0.6、没见过的内容）。

**成本**：交接方那个粗糙的量具（逐像素 Double 循环）花的 CPU 约为转换本身的 8 倍（258 张：转换
用户态 10 s，核对 80 s）。转换走硬件编码器很快，所以核对会成为批量耗时的大头。要用 Accelerate
（vImage / vDSP）之类把它做快，并量出真实的开销（§4.6）。

**内存**：一张 2400 万像素的图，两份 RGBA 8 位缓冲各 96 MB；交接方量具另开了两份 Double 亮度数组
（各 192 MB），按默认并发（核数）同时跑会吃掉十几 GB。不许这样：每张同时只留两份 8 位缓冲（或更省），
亮度/块统计边算边丢，峰值内存要量（§4.6）。

## 3. 设计（已定）

### 3.1 判据

产物写进临时文件之后、挪到目标位置之前核对（不达标的产物从不覆盖已有的文件）：

1. 源 JPEG 和产物各取第 0 张图，真解码（不要只拿 CGImage 不取像素），画进**同一个** RGB 8 位缓冲格式。
   色彩空间：源图的色彩空间是 RGB 的就两边都画进源图的色彩空间，否则 sRGB。不应用方向（两边方向标签相同）。
   宽高不同：算不达标，原因写「尺寸变了」。
2. **PSNR**：RGB 三通道 8 位的均方误差，`10·log10(255² / MSE)`；MSE 为 0 时视为无穷大（达标）。
3. **最差 1% 局部 SSIM**：亮度 `Y = 0.299R + 0.587G + 0.114B`；从左上角起切成不重叠的 16×16 块，
   右边、下边凑不满 16 的部分不算；每块按
   `((2μaμb + C1)(2σab + C2)) / ((μa² + μb² + C1)(σa² + σb² + C2))`，`C1 = (0.01·255)²`、
   `C2 = (0.03·255)²`，方差、协方差用 n−1；所有块升序排好，取下标 `⌊块数 / 100⌋` 那一个。
   宽或高不到 16：整张图当一块。
4. **不达标** = 局部 SSIM < 门槛 S，**或** PSNR < 门槛 P。默认 S = 0.90、P = 33 dB。

### 3.2 不达标时

两种处理方式，默认「不转」：

- **不转**：删掉产物，保留 JPEG。结果不是「转换成功」，单独一类（见 §3.4）。
- **提高质量再试**：用质量 0.95 把「编码 + EXIF 整块照搬」再做一遍（同一套代码，含照搬与自检），
  再核对一次。达标就用这一份（之后照常走「比原图大」「校验」「删源」那些规则）；仍不达标就按「不转」处理。
  用户设的质量已经 ≥ 0.95 时不重试，直接「不转」。重试的质量 0.95 是常量，不做成设置。

与现有的「产物比原图大时重编一次」的先后：先做现有那一步（拿到较小的那份），再核对画质。

`--delete-original`：不转的当然不删源；提高质量后达标的，照旧要同时满足校验通过、不比原图大才删。
`-n`（预演）不核对。

### 3.3 开关与设置

`ConversionOptions` 加（名字可以自定，语义如下），默认值在 `ConversionOptions.default` 里，命令行和界面同一份：

- 画质核对开/关，默认开；
- 门槛 S（默认 0.90）、P（默认 33）；
- 不达标时的处理：不转 / 提高质量再试，默认不转。

命令行（jpeg2heif；raw2heif 不接受这几个参数，给了就报错）：

- `--no-quality-check` 关掉；
- `--min-ssim <0–1>`、`--min-psnr <dB>` 设门槛，取值越界或不是数字报错（照现有 `-q` 的报错风格）；
- `--on-quality-drop skip|retry`（写法可以改得更顺，但要在 `-h` 和 README 里写清）。

界面：转换面板「高级」里加：「转完核对画质」勾选；两个门槛的输入（带单位和说明，例如
「局部相似度不低于 [0.90]」「PSNR 不低于 [33] dB」）；不达标时「不转，保留 JPEG」/「提高质量重编一次再判」
二选一。这几项**记住**（写进 `PanelSettings`，和「转完逐项校验」同一待遇），默认值取自
`ConversionOptions.default`。门槛输入非法时不让开始转换，或给出明确提示，二选一并写测试。

### 3.4 输出

命令行：

- 不转的那张，一行说明，例如
  `IMG_1.jpg  画质下降明显（PSNR 31.2 dB，局部 SSIM 0.862，门槛 0.90 / 33 dB），没有转换，保留原 JPEG`；
  选了「提高质量再试」时写明重试过：`…，用质量 0.95 重编后仍不达标（PSNR …，局部 SSIM …），没有转换，保留原 JPEG`。
- 提高质量后达标：`-v` 时多一行 `画质：质量 0.8 不达标（…），用 0.95 重编后 PSNR …，局部 SSIM …`；不带 `-v` 也要
  在状态说明里留一句（用户得知道这张用了更高的质量）。
- `-v` 时每张转换成功的多一行 `画质：PSNR 43.5 dB，局部 SSIM 0.979`。
- 批量汇总里单独计数：`N 个画质不达标，保留原 JPEG`（和「N 个比原图大」同一处）。退出码：不转的算不算失败，
  与「跳过」一致即可，写进 README。

界面：转换结果里这类照片单独标出（徽章/文字，与「失败」「跳过」可区分），能看到两个数和门槛；
活动条/汇总文案里算上它们。删源规则仍只认 Eclose 报告（`sourceDeleted`），界面不自己推。

## 4. 验收标准

1. `make test` 全绿；三个计数的变化逐条说明。
2. 判据单测：用合成的像素缓冲直接测 §3.1 的函数——完全相同（PSNR 无穷、SSIM 1）、已知 MSE 的
   PSNR 值、一块被破坏而其余相同（平均 SSIM 高、最差 1% 低，验证取的是分位数不是平均）、不足 16 的
   小图、宽高不同。门槛比较的边界（恰好等于门槛算达标）各一条。
3. 端到端（selftest）：
   - 默认设置转正常的夹具：达标，产物在，`-v` 有画质行，汇总没有不达标计数。
   - 让它不达标：`-q 0.4` 配一个高门槛（如 `--min-ssim 0.999`），或注入一个故意写坏图的编码器
     （`convert` 已有 `encode:` 注入口）。「不转」：没有产物、源在、输出行和汇总计数对；带 `--delete-original`
     源也在；目标位置原来就有同名文件时（配 `-f`）它没被覆盖或删掉。
   - 「提高质量再试」两种结局各一条：重编后达标（产物在、质量确实更高——例如产物比 0.4 那份大、核对数
     更好）；重编后仍不达标（没有产物）。用户质量已 ≥ 0.95 时不重试。
   - `--no-quality-check`：不核对，行为与现在逐字节相同。
   - raw2heif 给这几个参数报错；界面混批里的 RAW 不核对。
   - 参数非法报错。
4. 界面模型测试：设置的默认值、记住与读回、非法门槛的处理、结果分类与文案。
5. 变异，每条至少一个，全部要红：不比 PSNR、不比 SSIM、取平均不取分位数、门槛比较方向反了、不达标仍留
   产物、重试不换质量、重试后不再核对、设置不记住、默认关。报告里列变异与失败的断言。
6. 零噪声与成本：
   - `--no-quality-check` 的产物与 main 逐字节相同（串行跑，机器上没有别的转换）；默认开时产物也应相同
     （核对不改产物），`-v --verify` 输出只多出画质行。
   - 量开销：`test_pic/` 与夹具，开/关各跑一遍，给出墙钟时间、用户态 CPU 时间、峰值内存
     （`/usr/bin/time -l`），按默认并发。再单测一张 6000×4000 的夹具（`fixture` 能造多大就造多大，造不了
     就拿两张拼）。主会话会在用户的照片上复量。
7. 只动该动的：`Sources/Eclose`（判据、选项、转换流程、批量汇总）、`Sources/CLI`、`Sources/GUI`、测试、README。

## 6. 不做的

- RAW 的画质核对。
- 转换前按「像截图」「像图表」之类的特征预先剔除。
- 自动在多个质量之间搜索。只重试一次，质量 0.95。
- 第三方画质指标（SSIMULACRA、Butteraugli 等）；零依赖。
