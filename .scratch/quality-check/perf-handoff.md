`HANDOVER.md` 的「质量原则」「隐私规则」「工作方式」；功能本身见同目录 [`handoff.md`](handoff.md) 和 README「转完核对画质」。

- 计时、逐字节比较时机器上不能有别的转换或 `make test` 在跑（先 pgrep；另一个会话也在这个仓库工作）。

## 1. 现象（main = f63656a）

用户的 1733 张风景照（13.3 GB，最大 6000×4000，默认并发）：

| | 墙钟 | 用户态 | 系统态 | 峰值内存 |
|---|---|---|---|---|
| `--no-quality-check` | 112 s | 94 s | 33 s | 6.5 GB |
| 默认（核对开） | 173 s | 297 s | **383 s** | 7.9 GB |

核对多出来的系统态约每张 0.2 s，是大头。

## 2. 交接方量到的（6 张 6000×4000 相机 JPEG 与它们的 HEIC，单线程，`getrusage`）

| 做法 | 用户态 | 系统态 |
|---|---|---|
| JPEG：`CGImageSourceCreateImageAtIndex` + `dataProvider.data`（现在） | 0.13 s | **0.71 s** |
| JPEG：`vImageBuffer_InitWithCGImage` 解进复用的缓冲 | 0.10 | 0.66 |
| JPEG：画进 `CGContext(data: nil)`（新开） | 0.07 | 0.71 |
| JPEG：画进每次 `malloc` 的新缓冲 | 0.08 | 0.21 |
| JPEG：画进**复用**的缓冲 | 0.08 | **0.10** |
| HEIC：整幅 `dataProvider.data` | 0.11 | 0.22 |
| HEIC：512 行条带 + 上下 16 行余量（现在） | 0.18 | 0.44 |
| HEIC：1024 行条带 + 余量 | 0.14 | 0.32 |
| HEIC：2048 行条带 + 余量 | 0.12 | 0.25 |
| HEIC：画进复用的缓冲（整幅） | 0.13 | 0.30 |
| HEIC：512 行对齐 HEIC 图块、不带余量 | — | — （与整幅解码有 42 行不同，不能用） |

结论：系统态主要花在**每张图新分配的大块内存**上（缺页清零、归还），不在解码本身；JPEG 那一侧是大头，
HEIC 条带越小越贵。

**画进去的解码和 `dataProvider` 的解码不完全相同**：JPEG 每一行都有差，最大差 1 个色阶。对核对结果的影响
（4 张，产物同一份）：PSNR 低 0.24–0.42 dB（42.28 → 42.04 等），局部 SSIM 不变（0.9780 → 0.9781 等）。偏差方向是把
画质说得略差，离门槛很远。**接受这个偏差**（已定）。

## 3. 设计（已定的部分）

1. 源 JPEG 改为画进复用的缓冲（`CGContext` 用调用方提供的内存、`.copy` 混合、不插值，色彩空间沿用现有规则）。
2. 缓冲按「核对槽」复用：每个同时进行的核对一份（数目同 `qualityCheckSlots`），只增不减到这一批用到的最大尺寸；
   **一批转完要还给系统**（界面是常驻进程，不能一直占着）。线程安全要有单测或说明。
3. HEIC 一侧：在「画进复用的缓冲」「更高的条带（1024/2048 行）」「整幅 `dataProvider`」里选系统态最低、峰值内存
   不超过现在的那个，可以组合（例如条带画进复用的缓冲）。余量照旧（单测「按条带解产物与整幅相同」照旧要过——
   如果改成画进去，就改成「条带与整幅用同一条路解，逐字节相同」）。量完把数写进报告，选择理由写进代码注释。
4. 别的不变：判据、门槛、输出文案、并发上限的语义。

## 4. 验收标准

1. `make test` 全绿；计数变化逐条说明。期望值依赖具体像素的断言（如果有）因 §2 的偏差要改的，逐条列出旧值→新值。
2. 开销（主会话会在用户照片上复量，你在夹具上量）：
   - 18 张 6000×4000、36 张 4032×3024 两组，默认并发，`/usr/bin/time -l` 三次取中位：**核对多出来的系统态至少降 60%**
     （以 f63656a 为基线，开/关两种都量），墙钟不变差，峰值内存不高于 f63656a。
   - 一批转完后缓冲已还（例如在单测里查池子空了，或测进程转完一批后的常驻内存）。
3. 零噪声：`--no-quality-check` 的产物与 f63656a 逐字节相同；默认开时产物也相同（核对不改产物），输出只有画质行里的数可能变。
4. 变异，全部要红：缓冲不复用时（每次新分配）测试不该红——这一条不用；要红的是：不还缓冲、两个核对共用同一份缓冲
   （并发互踩）、条带余量去掉、源图改回 `dataProvider` 而没改期望值（如果有依赖像素的断言）。报告列变异与失败的断言。
5. 只动 `Sources/Eclose/QualityCheck.swift`、必要时 `Converter.swift` / `Batch.swift` 里调用它和还缓冲的地方、测试、README 的开销一节。

## 5. 不做的

- 不改判据和门槛，不改「源整幅解、产物分条」以外的流程顺序。
- 不碰编码路径（`CGImageDestinationAddImageFromSource` 那一路）。
