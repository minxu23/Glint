# MPF 索引登记的附加图像不在文件里时，要不要报

Status: needs-triage

## 现象

太和影像测试集 10 号（`01_案例样本/10_空EXIF与缺失辅助图/`）：主图完整、以 EOI 结束；APP2 的 MPF 索引
说主图 1,264,084 字节、另有一张 110,136 字节的增益图（类型码 0x050000），偏移在文件末尾之后——文件只有
659,382 字节。像是编辑软件重存了主图、扔了增益图、MPF 索引原样留着（文件名带 `-01`）。

现在：校验通过，`--delete-original` 会删源。测试集索引对这一案写的是「默认保留 JPEG；诊断候选只保留
现存内容，不能代表缺失辅助图已恢复」。

## 两种做法

- **不报（现状）**：源里本来就没有这张增益图，转换什么也没丢。`Tests/selftest.sh` 里「只有 ISO 21496
  标记段、没有增益图」那条就是这么定的，注释写明了理由。
- **报（补丁 `01-report-stale-mpf.patch`）**：`源文件不完整：MPF 索引登记的附加图像（类型码 0x050000，
  110136 字节）不在文件里，可能是截短了或编辑后留下的旧索引；产物里没有这张图`。一条差异，不删源。
  大尺寸预览图（0x010001/0x010002）不在不报——派生物，在文件里也不带。

## 补丁的验收（做在 b05e4d5 上）

- `make test` 全绿：自检 730，单测 1359（+4），界面模型 363；selftest 那条改成断言只报这一条。
- 2907 个畸形样本：157 个多了这一条（截在附加图像里的 140 个、MPF 条目被改坏的十几个），都是本来就
  报差异的，没有从「通过」变成「不通过」的；产物逐字节相同。
- 太和测试集：只有 10 号从「通过、删源」变成「报一条、保留」。

应用：`git apply .scratch/mpf-stale-index/issues/01-report-stale-mpf.patch`，再 `make test`，
README 的「截断的文件照样转得出来」一条补一句。
