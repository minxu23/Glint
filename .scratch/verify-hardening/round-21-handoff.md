## 2. 量到的事实（main = f167f2e）

### 2.1 整块照搬的路上，没有发现丢失

24 张里 exiftool 读产物全部读对；ImageIO 读产物与读源相同，其中 8 张（无前缀、全零头）从读不出
变成读得出。

### 2.2 `ASCII\0\0\0` 头 + UTF-8 中文：系统重写时被永久写成乱码，校验通过

- ImageIO 把这种值按 Latin-1 读（`è¥¿æ¹…`，不是空的），所以现在不算「读不出」、不修补。
- 整块照搬：字节原样过去，exiftool 读对，ImageIO 两边都是同一串乱码，校验通过——没丢。
- 系统重写（`--no-raw-exif`，或被自检挡回时）：ImageIO 把那串乱码当正文写成 `UNICODE`，
  产物里只剩乱码，exiftool 也读成乱码，**校验通过**。原文没了。

### 2.3 字节不是合法 UTF-8 的备注（例如 GBK）：现在按 Latin-1 猜

`decodeUserComment` 对无前缀、全零头、ASCII 头的值，UTF-8 解不出就退到 Latin-1。Latin-1 永远
解得出，所以 GBK 的备注被「解」成一串西欧字符：

- **无前缀 + GBK，默认路径**：第 20 轮的备注改写生效，0x9286 改指到 `UNICODE` + 那串乱码；
  GBK 字节还在块里但没人引用了。校验通过。
- **无前缀 + GBK、ASCII 头 + GBK，系统重写**：产物里是 `UNICODE` + 乱码（`00ce 00f7 00ba…`，
  每个字节一个码位）。校验通过。
- ASCII 头 + GBK，默认路径：字节原样照搬，没丢。

Latin-1 的猜测对西欧文字是对的，对 GBK 是错的，工具分不出来。

### 2.4 系统重写写出的纯中文备注，exiftool 读成乱码

`userCommentForHEIFWriter` 只在首个单元是 ASCII 时才加 BOM。首字符是中文时写出的是
`UNICODE\0` + 大端 UTF-16（无 BOM）+ 一串 NUL；ImageIO 读得对，exiftool 猜错字节序读成乱码
（`膜癬ɞ…`）。量过：**总是带 BOM**（BOM + 文本 + 同样多的 NUL，也就是现在「首单元是 ASCII」
那一支的做法），exiftool 读对，ImageIO 仍读对，纯中文、中英混排、ASCII 开头三种都试了。

### 2.5 这一轮不碰的

`UNICODE` 头、没有 BOM 的备注，ImageIO 一律按大端读；小端 EXIF 里按小端写的这种备注 ImageIO
读成乱码（源和产物一样，字节完好）。要修得判断真实字节序，现有的 `moreReadable` 对纯中文分不出
两种字节序（都是可打印字符，打平取大端）。用户已决定先不做。**这一轮不改 `UNICODE` 备注的
任何判断。**

## 3. 设计（已定）

### 3.1 备注的读法分「可靠」和「猜的」

把 `decodeUserComment` 的结果分成三种（名字你定）：

- **没有**：没有 0x9286，或去掉填充后是空的。
- **可靠的文本 T**：
  - `UNICODE\0` 头：有 BOM 认 BOM，没有就照现在的规则（`moreReadable`）——这一支行为不变。
  - `JIS` 头：Shift-JIS 解得出。
  - `ASCII\0\0\0` 头、8 个 0 的头、没有头：去掉填充后的字节全是 ASCII，或是合法的 UTF-8。
- **猜的**（附带原始值字节）：上面最后一类里字节含 ≥ 0x80、又不是合法 UTF-8 的；`JIS` 头解不出的。
  Latin-1 解出来的那串只是猜测。

### 3.2 什么时候修补（源侧视图、整块照搬时的备注改写、校验认改写，三处同一个判断）

现在是「ImageIO 读不出 且 自己解得出」。改成：

1. ImageIO 读不出（去掉填充后为空）且备注是**可靠的文本** T；或
2. 备注是 `ASCII\0\0\0` 头、字节含非 ASCII、是合法 UTF-8（2.2）——不管 ImageIO 读成什么。

满足时：源侧视图里的 `{Exif}/UserComment` 是 T（`repairedProperties`）；系统重写写 T；整块照搬
按第 20 轮的办法改写成 T。

**猜的备注不进源侧视图，整块照搬时不改写**：照搬的是源的原样（字节一个不动），ImageIO 读它
和读源一样（读不出，或读成同一串 Latin-1）。这样 2.3 的默认路径不再把 GBK 改指成乱码。

系统重写那条路对「ImageIO 读不出、猜的」备注，照旧把 Latin-1 猜出来的那串写进产物（只进写入
用的属性，像 `propertiesToWrite` 补 ImageUniqueID 那样，不进源侧视图）：Latin-1 一个字节对一个
码位，原字节还能从产物里一一还原，比不写强；写了之后由 3.4 的校验报出来。

### 3.3 系统重写时非 ASCII 的备注总是带 BOM

`userCommentForHEIFWriter`：含非 ASCII 的备注一律在最前面放 BOM（现在只有首单元是 ASCII 时放），
其余不变。纯 ASCII 的备注原样返回，不变。

### 3.4 校验：两边备注的原文必须相同

键空间比对比的是 ImageIO 两边读出来的值；ImageIO 把源读错了、又把读错的写进产物，两边一样，
它看不见（2.2、2.3）。加一条按原始字节的核对（源读 JPEG 的 EXIF，产物读 HEIF 的 Exif 项，
都用 3.1 的读法）：

| 源的备注 | 产物必须 | 否则报 |
|---|---|---|
| 没有 | —— | —— |
| 可靠的文本 T | 也是可靠的文本，且等于 T | `变化 备注 UserComment 的原文：T → …`（产物没有备注是 `丢失 备注 UserComment 的原文 = T`） |
| 猜的 | 0x9286 的值字节与源的逐字节相同 | `变化 备注 UserComment：源里的字节不是合法的 UTF-8（N 字节），产物里换了一种写法，原文无法核对`（产物没有备注是 `丢失 备注 UserComment（N 字节，不是合法的 UTF-8）`） |

- 比文本之前两边都去掉开头的 BOM、尾部的 NUL 和空白（与键空间比对的 `trimPadding` 同一把尺子）。
- 产物的 EXIF 读不出时已有「无法核对原始 EXIF 标签」那一行，这里不再重复。
- 同一处问题只出一行：键空间比对已经为 `{Exif}/UserComment` 报了丢失或变化的，这一条不再报
  （沿用 `covered` / `viewLosses` 那套互相让位的做法，方向你定，说明理由）。
- 整块照搬且没改写的产物，两边字节相同，这一条恒过；改写过的，产物是可靠的文本 T，也过。

措辞可以调整，但三种情形要分得开，并且写清楚是「原文」而不是视图里的值。

## 5. 验收标准

### 5.1 见证（端到端；造样本用 `mangle`，需要就扩展它；大端、小端各做）

1. **ASCII 头 + UTF-8 中文**：
   - 默认路径：`-v` 说照搬并改写了备注；校验通过；`probe --no-repair` 从产物读出的备注等于原文；
     probe `--exif-same` 报「只差备注改写」。
   - `--no-raw-exif`：校验通过；从产物读出的备注等于原文。
2. **无前缀 + GBK**（字节不是合法 UTF-8）：
   - 默认路径：照搬、`-v` 里**没有**「改写」；probe 报「相同」；校验通过；`--delete-original` 删源。
   - `--no-raw-exif`：校验报 3.4 第三行那种差异；`--delete-original` 不删源。
3. **ASCII 头 + GBK**：默认路径同上（相同、通过）；`--no-raw-exif` 报出。
4. **无前缀 + Latin-1 西欧文字**（如 `café`，字节 E9）：与第 2 项相同的结果（工具分不出它和 GBK）。
5. **纯中文的 `UNICODE` 备注**（普通夹具就是）：`--no-raw-exif` 的产物里 0x9286 的值以
   `UNICODE\0` + `FEFF` 开头；ImageIO 读回等于原文；校验通过。
6. **3.4 零噪声**：普通夹具、`unicode备注`、中英混排、ASCII 开头的中文、纯 ASCII、带尾部 NUL 或
   空格填充的备注、`test_pic` 两张（IMG_1225 的备注是 264 字节全零）：两条路的校验都不因 3.4
   多出任何一行。
7. **2.5 不变**：小端 EXIF + `UNICODE` + 小端 UTF-16（无 BOM）：两条路的产物和校验输出与
   f167f2e 的行为一致（默认路径逐字节照搬；不新增报告）。

### 5.2 单测

- 3.1 的读法：每种头 × ASCII / UTF-8 / 非法 UTF-8 / 空 / 只有填充；`UNICODE` 带 BOM（两种字节序）
  与不带；`JIS` 解得出与解不出。
- 3.2 的判断：真值表（ImageIO 读成空 / 读成乱码 / 读对 × 备注三种）。
- 3.4 的比较（纯函数，喂两边的原始值）：表里每一格的「过」与「报」；BOM、尾部 NUL、空白的归一；
  让位规则。
- 3.3：纯中文、中英混排、ASCII 开头、已带 BOM、带尾部 NUL、纯 ASCII。

### 5.4 零噪声与不退步

- 默认路径：备注是「没有」、纯 ASCII、或 ImageIO 读得对的 `UNICODE` 且首字符是 ASCII 的输入，
  产物与 f167f2e 逐字节相同。备注含非 ASCII 的输入，ImageIO 先写出的那份 EXIF 因 3.3 多了一个
  BOM，照搬时清零的旧范围长度跟着变，产物不再逐字节相同——对这些输入改为核对：probe
  `--exif-same` 的结果与 f167f2e 相同，解码像素相同，`-v --verify` 输出逐行相同。
- `--no-raw-exif`：同样的划分；含非 ASCII 备注的，`--verify` 输出逐行相同，ImageIO 读回的备注相同。
- 所有夹具两条路：`--verify` 的差异行相对 f167f2e 只因 3.4 的三种情形增加，逐条列出是哪些样本、
  哪一行。

### 5.5 健壮性

3.1 的读法和 3.4 的比较对任意字节不崩（截断、翻位、随机）；带各种备注的源 JPEG 的 EXIF 段
逐字节翻位走完整转换不崩（大端样本做全，小端的可以抽样）。
