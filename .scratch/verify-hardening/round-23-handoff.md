# 第 23 轮交接稿：EXIF 与 IPTC 打架的照片也整块照搬（保留 EXIF 的原值）

[`round-12-handoff.md`](round-12-handoff.md) 的第 0 节，先读那一节。另加：

  拷二进制出去用之前先确认它是还原之后重编的。

分三批：**A 自检放行 → B 校验 → C 文档**，一批一提交，全绿就提交。全部做完再交报告。

## 1. 背景

EXIF 整块照搬之后有一道「视图不退步」的自检（`rawExifRegression`）：照搬后只要有一个视图键从
「与源一致」变成「不一致」，就退回系统重写。现在还会因此退回的主要是 **EXIF 与 IPTC（IIM）
内容打架**的照片：JPEG 里 ImageIO 用 IIM 的值调和出说明、作者、版权，写进产物的 EXIF 和 XMP；
照搬后产物里的 EXIF 是源的原值，HEIC 里 EXIF 压过 XMP，视图里的值就变了。退回系统重写的代价
是丢 MakerNote、GPS 精度等。用户决定：这类照片也照搬，**保留 EXIF 的原值**，显示值的变化由
校验照实报出来。

## 2. 交接方量到的事实（main = 4b68663）

两张有代表性的样本（都来自畸形样本库，你拿不到；配方见第 5 节），三种做法各试了一遍
（原样照搬用 `round-18-repro/exifswap.py` 的布局）。

### 2.1 IIM 的说明与 EXIF 的说明不同（EXIF：`西湖日落 sunset at West Lake`，IIM：`IPTC 备注字段`）

| | ImageIO 显示的说明 | 文件里 EXIF ImageDescription | 文件里 XMP dc:description |
|---|---|---|---|
| 源 JPEG | IIM 那份 | EXIF 那份 | IIM 那份 |
| 系统重写的产物（现在） | IIM 那份 | **被换成 IIM 那份** | IIM 那份 |
| 原样照搬的产物 | **EXIF 那份** | EXIF 那份（原样） | IIM 那份 |

现行校验对「源 → 原样照搬的产物」报三行：`变化 XMP/dc:description[x-default]`、
`变化 {IPTC}/Caption/Abstract`、`变化 {TIFF}/ImageDescription`，都是 `IIM 那份 → EXIF 那份`。
对系统重写的产物：0 处差异——EXIF 里原来那份被换掉了，没有任何一行。

### 2.2 IIM 的字符集标记坏了，ImageIO 把 IIM 读成乱码；EXIF 里是好的中文

| | ImageIO 显示 | 文件里的 EXIF | 文件里的 XMP |
|---|---|---|---|
| 源 JPEG | 乱码（说明、作者） | 好的 | 好的 |
| 系统重写的产物（现在） | 乱码 | **被写成乱码** | **被写成乱码** |
| 原样照搬的产物 | 好的 | 好的（原样） | 乱码 |

系统重写的产物校验 0 处差异：好的 EXIF 文本被永久写成乱码，校验通过。

### 2.3 涉及哪些键

畸形样本库 2266 个能转出的样本里，现在因视图退步被挡回的 78 个：73 个是说明（上面三个键），
4 个是作者（`XMP/dc:creator[0]`、`{IPTC}/Byline[0]`、`{TIFF}/Artist`），其余是时间。
版权同理（`XMP/dc:rights[x-default]`、`{IPTC}/CopyrightNotice`、`{TIFF}/Copyright`）。

## 3. 设计（已定）

三组「调和字段」，每组一个 EXIF 标签和它在视图里的几个键：

| 组 | EXIF 标签（IFD0） | 视图键 |
|---|---|---|
| 说明 | ImageDescription 0x010E | `{TIFF}/ImageDescription`、`{IPTC}/Caption/Abstract`、`XMP/dc:description[…]` |
| 作者 | Artist 0x013B | `{TIFF}/Artist`、`{IPTC}/Byline[…]`、`XMP/dc:creator[…]` |
| 版权 | Copyright 0x8298 | `{TIFF}/Copyright`、`{IPTC}/CopyrightNotice`、`XMP/dc:rights[…]` |

「EXIF 的原文」= 源 EXIF 里那个标签的值字节，去掉尾部 NUL 与空白后是 ASCII 或合法 UTF-8 的文本
（与第 21 轮备注的「可靠」同一个标准）；不是的话这一组不适用下面的放行。

### 3.1 A：自检放行（`rawExifRegression` 第 3 条）

照搬后新变得不一致的键（`inconsistentKeys(后) − inconsistentKeys(前)`）现在一个都不许有。改成：
其中属于上面某一组、且**照搬后这个键的值等于该组 EXIF 的原文**（同一把比较的尺子：
`valuesMatch` / `trimPadding`）的，放行；别的仍然一个都不许有。

也就是：产物只是如实显示了源自己 EXIF 里写的东西，不算退步。时间字段的打架不在这一轮
（照旧退回系统重写）。

`-v` 那一行说明哪几组保留了 EXIF 的原值，例如
`EXIF 整块照搬（786 字节；说明、作者与 IPTC 不一致，保留 EXIF 的原值）`。与第 20 轮的备注改写可以
同时出现。

### 3.2 B：校验

1. **打架的那一组合成一行，说清楚是怎么回事**。`源 → 产物` 满足：源里该组 EXIF 的原文 A 可靠；
   源的视图里该组某个键的值 V ≠ A；产物的视图里那个键的值 = A——就是这一轮放行的情形。这时不出
   那两三行各自的 `变化 键: V → A`，改出一行（措辞可调，要点不能少）：
   `变化 说明：源里 EXIF 与 IPTC 不一致，ImageIO 原来显示「V」，产物显示 EXIF 的原值「A」`
   它**算差异**（校验不通过，`--delete-original` 不删源）。该组里别的键如果是别的变法
   （既不是 V 也不是 A），照旧各报各的。用现有的 `covered` 机制让位，不要两处都报。
2. **三个文字标签的原文核对**（与第 21 轮的备注原文核对同形，针对系统重写那条路上的静默替换，
   见 2.1、2.2 的第二行）：源 EXIF 里这三个标签的原文可靠（A）时，产物原始 EXIF 里同一个标签
   解出来必须等于 A；否则报
   `变化 EXIF 说明 ImageDescription 的原文：A → B`（产物里没有这个标签是 `丢失 … 的原文 = A`）。
   源的值字节不是可靠文本的（如 GBK），要求产物的值字节与源逐字节相同，否则报
   `变化 EXIF 说明 ImageDescription：源里的字节不是合法的 UTF-8（N 字节），产物里换了一种写法，原文无法核对`。
   - 比较前去掉尾部 NUL 与空白；全空的当作没有。
   - 同一处已经有一行了就不再报：原始清点报了这个标签丢失的、键空间比对为 `{TIFF}/…` 那个键
     报了丢失或变化的（含上面第 1 条合成的那一行）。
   - 整块照搬的产物两边字节相同，这一条恒过。
   - Copyright 是「摄影师\0编辑者\0」两段的写法：两段都算原文的一部分（按值的全部字节比，
     只去掉最尾部的填充），先量 ImageIO 重写时怎么处理它，如果量到会丢第二段，这一条就该报出来；
     把量到的结果写进报告。

### 3.3 不变的

- 时间字段打架、其它原因的视图退步：照旧退回系统重写。
- `--no-raw-exif` 的产物与 4b68663 逐字节相同（这一轮不改系统重写写什么），只是校验可能多出
  3.2 第 2 条的行。

## 4. 现有断言怎么处理

- `只改IIM`（时间打架）：默认路径照旧退回系统重写，产物不变；校验输出会多出 3.2 第 2 条的一行
  （EXIF 说明的原文被换成了 IIM 的），相关断言按新输出改，逐条说明。
- 断言「无前缀加只改IIM」等退回旧路的：同理，逐条核对。
- 其余变红的是真退步，修代码。

## 5. 验收标准

### 5.1 见证（端到端；需要就扩展 `mangle`，例如加一个只改 IIM 某个数据集的操作）

1. **只有说明打架**：普通夹具，只改 IIM 的说明（2:120）、别处不动（IIM 摘要因此对不上，ImageIO
   改用 IIM 的值）。前提断言：源的 `{TIFF}/ImageDescription` 是 IIM 那份，不等于 EXIF 的原文。
   - 默认路径：照搬了，`-v` 说保留 EXIF 的原值；`--exif-same` 是「相同」；产物的
     `{TIFF}/ImageDescription` 等于 EXIF 的原文；校验恰好 1 处差异，就是 3.2 第 1 条那一行；
     `--delete-original` 不删源。
   - `--no-raw-exif`：校验报 3.2 第 2 条的 `变化 EXIF 说明 ImageDescription 的原文`；不删源。
2. **作者打架、版权打架**：各一张（或合在一张里），同上；合在一张时每组一行。
3. **IIM 读成乱码、EXIF 是好的**（2.2 的情形：去掉 IIM 里声明 UTF-8 的 1:90 数据集，或等价做法）：
   默认路径照搬，产物里 ImageIO 读出的说明、作者是好的中文，校验报那两组各一行；
   `--no-raw-exif`：校验报原文变化（好的中文 → 乱码），不删源。
4. **时间打架**（现有的 `只改IIM`）：默认路径仍然没照搬，产物与 `--no-raw-exif` 逐字节相同。
5. **不该放行的不放行**：EXIF 的原文不可靠（说明是 GBK 字节）又与 IIM 打架 → 照旧退回；
   打架的组之外另有一个键退步（比如再叠加一个缺字符集头而改写不了的备注）→ 照旧退回。
6. **不打架的零噪声**：所有不打架的夹具、`test_pic` 两张，两条路的校验都不因这一轮多出任何一行。

### 5.2 单测

- 放行规则的真值表：新退步的键属于某组且等于 EXIF 原文 → 放行；等于别的值 → 不放行；
  不属于任何组 → 不放行；EXIF 原文不可靠 → 不放行；三组各一例；带下标的键（`dc:creator[0]`、
  `dc:description[x-default]`）。
- 3.2 第 1 条：合成一行并让位；组内另有别的变法时各报各的；三组同时打架出三行。
- 3.2 第 2 条：相等不报；不等报；产物没有报丢失；不可靠时比字节；尾部 NUL、空白的归一；
  全空当没有；各条让位；Copyright 两段。

### 5.3 变异（每条亲眼看红，贴红的那几行）

| 变异 | 必须红在 |
|---|---|
| 去掉放行（恢复一个都不许） | 5.1 第 1–3 项默认路径「照搬了」 |
| 放行不比值（属于那几组的键一律放行） | 5.2「等于别的值 → 不放行」 |
| 放行不看 EXIF 原文是否可靠 | 5.1 第 5 项、5.2 |
| 3.2 第 1 条去掉（不合成） | 5.1 第 1 项「恰好 1 处差异」 |
| 3.2 第 1 条合成了但不算差异（校验通过） | 5.1 第 1 项「不删源」 |
| 3.2 第 2 条去掉 | 5.1 第 1、3 项 `--no-raw-exif` 的报出 |
| 3.2 第 2 条比较前不去尾部填充 | 5.1 第 6 项或 5.2 |

### 5.4 零噪声与不退步

- `--no-raw-exif`：所有夹具、`test_pic/` 两张，产物与 4b68663 逐字节相同；`--verify` 输出只因
  3.2 第 2 条增加，逐条列出是哪些样本、哪一行，并说明每一行是不是真的（源 EXIF 的原文确实被换了）。
- 默认路径：不打架的输入，产物与 4b68663 逐字节相同、输出逐行相同。
- 交接方合并前会用用户的真实测试集原件跑一遍，那里出现任何新的一行都要有解释。

### 5.5 健壮性

放行规则和两条校验对任意字节不崩；IIM、EXIF 段逐字节翻位的源走完整转换不崩。
