# 第 18 轮交接稿：EXIF 整块照搬

工作规则、长期要求、变异与 mtime 陷阱的注意事项，全部沿用
[`round-12-handoff.md`](round-12-handoff.md) 的第 0 节，先读那一节。另加两条：

- 变异后用 `cp -p` 从快照还原会连旧 mtime 一起还原，make 不重编，下一次测的还是变异版。
  还原后 `touch` 源文件，并确认那次 `make test` 的输出里有 swiftc 那行。
- **编码结果受机器负载影响**：两个进程同时在编码时，同一张图的产物大小会差出 20%（实测）。
  凡是要「逐字节相同」的比较，期间不要并行跑别的转换或别的 `make test`。

这一轮比以往大，分三批：**A 容器改写与闸门 → B 校验 → C 文档**，一批一提交。全部做完再交
报告（不用每批停下等验收）。

## 1. 目标

现在 EXIF 的路是「ImageIO 读成字典 → ImageIO 从字典写出去」，它不认识的东西在这一读一写里
就没了：各家 MakerNote、规范新标签、不合规范的写法、GPS 秒的精度。前几轮是丢一个补一个
（UserComment、ImageUniqueID）。这一轮换路：**像素、增益图、ICC、XMP 照旧交给 ImageIO，写完
以后把产物里 Exif 项的内容换成源文件 EXIF 段的原始字节**。ImageMagick 就是这么做的（EXIF
当不透明字节块整块交给 libheif）。

不能照搬的情形（见 3.3）退回现在的路，行为与现在逐字节相同。

## 2. 交接方量到的事实（main = abc3b7b）

量具在 [`round-18-repro/`](round-18-repro/)：`exifswap.py`（探针，`swapx` 是定稿的布局）、
`chk.swift`（ImageIO 读回：属性、像素哈希、转正缩略图、辅助图）、`thumb.swift`、`fzone.sh`。
只供参考写法，测试不得依赖。样本是六种夹具、`test_pic/` 两张、4 张公开 HDR 样本、10 张
私人照片（后两类不在仓库里，你拿不到，也不需要）。

### 2.1 ImageIO 写出的 HEIC 长什么样

33 个产物全部是同一种布局：

- 顶层 `ftyp`、`meta`、`mdat` 各一个，`mdat` 在最后，盒头 8 字节（32 位长度）。
- `iloc` 版本 0 或 1，offset_size = length_size = 4，base_offset_size = 0。
- Exif 项恰好一个，构造方式 0，一段，数据在 `mdat` 里靠前的位置（图像数据之前）。
- Exif 项的内容：`00 00 00 06` + `Exif\0\0` + TIFF（ImageIO 一律写成大端 `MM`）。
- 源里的 EXIF 是空 IFD（16 字节）时，产物里**没有** Exif 项。

### 2.2 替换之后 ImageIO 读回

30 个有 Exif 项的产物全部替换（新内容接在 `mdat` 末尾，`iloc` 指过去）。与替换前逐项比：

- 像素哈希、按方向转正的缩略图、HDR 解码、五种辅助图的数据：**全部相同**。内容余量
  （`Tests/probe --headroom`）6 张带增益图的样本替换前后相同。
- 属性视图只多不少：佳能、松下、富士的样本多出 `{MakerCanon}`、`{ExifAux}`、`{PictureStyle}`
  （ImageIO 从 HEIC 里解析出了 MakerNote，说明内部偏移没错位）；`{GPS}/Latitude`、
  `{Exif}/ExposureTime` 等从被截断的值变回源的精确值；按规范写的 `{GPS}/ProcessingMethod`、
  `AreaInformation` 出现了。没有一个键变少或变错。
- 「新开一个 `mdat` 放在文件末尾」和「把原 `mdat` 加长」两种布局读回完全相同。定稿用后者。

### 2.3 exiftool 逐标签比

`exiftool -a -u -U -G1 -s -n -EXIF:all -MakerNotes:all -GPS:all`，源 vs 产物：

| 样本 | 源的标签数 | 现在缺 | 替换后缺 |
|---|---|---|---|
| 佳能（`test_pic/IMG_1225.JPG`） | 2885 | 2849 | 0 |
| 松下（`test_pic/P1130939.JPG`） | 290 | 249 | 0 |
| 华为（私人） | 92 | 34 | 0 |
| 富士（私人） | 122 | 76 | 0 |
| Ultra HDR 样本 | 13841 | 9 | 0 |

唯一的不同是 `IFD1:ThumbnailOffset` 的显示值——exiftool 报的是文件里的绝对位置，换了容器自然
不同。`exiftool -b -ThumbnailImage` 取出的缩略图与源逐字节相同。

`exiftool -validate` 对带 IFD1 缩略图的产物多报一条 `IFD1:ThumbnailOffset is past end of file`：
它把基址加了两遍（报出的偏移 = 真实位置 + Exif 项的文件偏移），是 exiftool 对 HEIC 里 IFD1
的算法问题，取图不受影响。写进 README 的已知限制。

### 2.4 方向与内嵌缩略图

同一张图把 Orientation 设成 1、3、5、6、8 各转一次：产物里 `irot`/`imir` 由 ImageIO 按源的
方向写好；替换前后 `Orientation`、`{TIFF}/Orientation`、像素、转正缩略图全部相同。HEIC 读取器
不用 EXIF IFD1 里的缩略图（`CGImageSourceCreateThumbnailAtIndex` 不带任何选项时两边都返回 nil）。

### 2.5 现行校验对替换后的产物怎么说

用 5cd36ee 的 `metadataDiff` 比「源 vs 替换后的产物」：EXIF 这一层的差异行全部消失
（MakerNote、PrintImageMatching、ImageUniqueID、GPS 秒的精度、类型不合规范的标签、放错 IFD 的
标签），只剩 HEIF 里本来就没处放的东西（APP2 FPXR、APP7–10、APP8、EOI 之后的数据）。
没有一张样本多出新的差异行——除了下面 2.6 的三种。

### 2.6 三种不能直接照搬的情形（用测试套件里现成的配方量到）

1. **`无前缀`（缺字符集头的 UserComment）**：现在转换时会修补成 ImageIO 读得出的写法；照搬后
   产物里是源的原样，ImageIO 读不出，校验报 `丢失 {Exif}/UserComment`。照搬让这张图**退步**。
2. **`只改IIM`（EXIF 与 IIM 打架）**：JPEG 里 ImageIO 调和出的 `{TIFF}/ImageDescription` 取的是
   IIM 的值，并把它写进了产物的 EXIF 和 XMP；照搬后产物的 EXIF 是源的原始值，HEIC 里 EXIF 压过
   XMP，视图里的标题变成了另一个。校验从 2 处差异变成 5 处（`XMP/dc:description`、
   `{IPTC}/Caption/Abstract`、`{TIFF}/ImageDescription` 新变了）。
3. **`只有XP`、`XP不同值`（Windows XP 标签）**：标签原样在产物的 IFD0 里了，但
   `windowsTagLosses` 只认「等价字段带着同一个值」，照旧报丢失。这是校验要改的（见 4.1）。

第 1、2 种由 3.3 的「不退步」自检统一处理：照搬会让任何一个视图键从「与源一致」变成「不一致」
时，就不照搬。

### 2.7 健壮性

前几轮攒下的 2907 个畸形 JPEG（截断、翻位、改长度、改偏移），现行版本能转出产物的 2266 个：

- 10 个源里没有 EXIF 段，不换；其余 2256 个全部替换。
- 替换后 ImageIO 读回：状态、像素哈希、转正缩略图、辅助图与替换前**全部相同**，没有崩溃、
  没有挂起。
- 用现行 `metadataDiff` 比替换前后：237 个差异变少，1935 个不变，84 个变多。变多的（按条目
  算是 87 个样本）只有 2.6 那两种：73 个是 `{TIFF}/ImageDescription`、`{IPTC}/Caption/Abstract`、
  `XMP/dc:description` 三个一起变（IIM 被改过，JPEG 里 IIM 压过 EXIF），4 个是 Artist/Byline/
  `dc:creator` 同理，9 个是 `{Exif}/UserComment` 读不出，1 个是时间字段。都该被 3.3 的自检
  挡回旧路。

### 2.8 没量的

- 照片 App、预览、访达：没有单独操作，它们都走 ImageIO，ImageIO 的读回量过了。
  `sips -g all` 替换前后输出相同，`qlmanage -t` 生成的缩略图逐字节相同，`sips` 把产物转回
  JPEG 成功。`mdimport -t` 在这台机器上对替换前的文件也崩，量不了。
- libheif、Windows、安卓的读取器：本机没有，没量。结构上与 ImageMagick/libheif 的产物同类
  （EXIF 不是 ImageIO 写的）。

## 3. 设计（已定，按这个做）

### 3.1 开关

`ConversionOptions` 加一个布尔量，默认开。命令行加 `--no-raw-exif` 关掉它（帮助里写：
EXIF 交给系统重写、不整块照搬；遇到读不了产物的软件时用）。图形界面不加开关，用默认值。

关掉时的产物和校验输出必须与 abc3b7b **逐字节、逐行相同**。

### 3.2 容器改写（批 A 的核心，纯函数：进产物字节与源 EXIF 字节，出新字节或「不换」的原因）

放在 `encodeHEIF` 成功之后、拷贝文件时间和扩展属性之前，对临时文件做。

**闸门**——任何一条不满足就不换，产物保持 ImageIO 写出来的样子，不算错误。拿不准就不换：

源一侧
- JPEG 里恰好一个 `Exif\0\0` 开头的 APP1 段，内容是合法的 TIFF 头（`TIFFStructure` 读得通）。
  源里没有 EXIF 段：无事可做。

产物一侧（复用并扩展 `HEIFExif.swift` 的解析，所有长度、偏移一律不信，越界就不换）
- 恰好一个 Exif 项；`iloc` 里它恰好一段，构造方式 0，data_reference_index 0。
- 原内容开头的 4 字节偏移不超过一个小的上限（比如 64），前缀原样保留。
- 原内容的范围整个落在某个顶层 `mdat` 里，并且**不与 `iloc` 里任何别的项的任何一段重叠**
  （要清零，重叠就会毁掉别人的数据）。
- 顶层最后一个盒子是 `mdat`。它的长度字段是 32 位、64 位（size == 1）、或「到文件末尾」
  （size == 0）三种都要处理对；32 位放不下新长度时不换（不要去改盒头的宽度）。
- 新偏移、新长度放得进 `iloc` 现有的 offset_size / length_size（4 或 8）。
- 产物的 TIFF 字节已经与源相同：无事可做。

**改写**（除下面四处，旧文件末尾之前的每一个字节都不动——图像数据的位置一个都不挪）：

1. 新内容 = 原前缀（4 字节偏移 + `Exif\0\0`）+ 源的 TIFF 字节，接在文件末尾（也就是最后那个
   `mdat` 的末尾）。
2. 最后那个 `mdat` 的长度字段加上新内容的长度（size == 0 时不用改）。
3. Exif 项在 `iloc` 里的偏移和长度指向新内容。
4. 原内容所在的范围**清零**。不能留着：那是一份没人引用的旧 EXIF（含 GPS），以后用户拿别的
   工具删了位置信息，这份死数据还在文件里。

源的 TIFF 字节**一个不改**：不摘 IFD1 缩略图，不改方向，不改尺寸。像素没有旋转也没有缩放，
源的值就是对的。

### 3.3 改完的自检（不退步）

改写得到新字节之后、落盘之前，在内存里核对；任何一条不过就丢掉新字节、保留原产物：

1. 用 `heifExif` 从新字节里重新取出 Exif 项，TIFF 字节与源逐字节相同。
2. ImageIO 打得开，状态完整，图像数、顶层 `PixelWidth`/`PixelHeight`/`Orientation` 与改写前相同。
3. **视图不退步**。记 V源 = `--verify` 用的源侧键空间（`metadataDiff` 里的 `before`，含原始时间
   字段那一步），V前 = 改写前产物的键空间，V后 = 改写后的。用 `keySpaceDiff` 自己的那把尺子
   算「与源不一致的键」的集合（缺失也算不一致；尺子本来就不比的易变键不算）：
   **V后 的不一致集合必须是 V前 的不一致集合的子集**。原来一致的键，一个都不许变坏。
   把这把尺子从 `keySpaceDiff` 里抽成一个函数，校验和这里用同一个，不要另写一份。

   这一条不是保险，是必需的：2.6 的第 1、2 种就靠它退回旧路。

落盘要原子（写到另一个临时文件再替换，或等价做法），中断不能留下半个文件。

### 3.4 让人看得见

`-v` 时每张图多一行：照搬了（多少字节），或没照搬（原因，例如「照搬后 {Exif}/UserComment 会读不出」
「源里的 EXIF 段不止一个」）。不带 `-v` 时不出这一行，校验结果、备注、图形界面都不变。

## 4. 校验（批 B）

`--verify` 照旧只看两个文件，不知道也不该知道转换时走了哪条路。

### 4.1 Windows XP 标签

产物原始 EXIF 的 IFD0 里有同一个标签、解出来的值相同，也算承载（现在只认等价字段）。
`只有XP`、`XP不同值` 在默认路径上应当通过；`--no-raw-exif` 下照旧报那几行。

### 4.2 照搬过的产物必须与源逐字节相同

原始清点对非 GPS 标签只看在不在，不比值（改写路径上值的写法本来就会变，逐值比只会刷噪声）。
照搬之后产物里多了一大批以前不可能出现的标签（MakerNote、私有标签），它们的字节对不对，
视图和清点都看不见。补一条结构性的规则，不看标签语义：

> 产物的 Exif 项的内容位于文件最末尾（ImageIO 自己写的产物里它在 `mdat` 靠前的位置，
> 永远不会在末尾——先用现有夹具确认这一点，确认不了就来问）⇒ 这是照搬过的产物 ⇒ 它的 TIFF
> 字节必须与源的 EXIF 逐字节相同。不同就报一行：
> `变化 EXIF 数据块：照搬过来的 EXIF 与源不一致（N 字节 → M 字节，第 K 个字节起不同）`

改写路径的产物永远不触发这一条，零噪声。逐字节相同的产物，现有的原始清点、GPS 分数、
ImageUniqueID 各条规则自然全过，不用为它们加分支。

### 4.3 其余不动

键空间比对、原始时间、APP 段与尾部记账、辅助图，全部不动。跑完整套测试如果有别的规则在
默认路径上报出了新行，先判断是真退步（交给 3.3 的自检去挡）还是规则像 4.1 那样没跟上
（那就写进报告，说明你怎么改的、为什么）。

## 5. 现有断言怎么处理

默认路径变了，会有一批现有断言变红。逐条按下面的规则处理，不要成批改期望值：

- 断言的是「ImageIO 重写 EXIF 造成的丢失被报出来」（MakerNote 汇总行、`ImageIO 没有把它写进
  产物`、`HEIF 写入器只保留到 1/100 秒`、类型不合规范、放错 IFD 等）：**原断言加上
  `--no-raw-exif` 保留**——那条报告路径仍是产品行为（不照搬时走它），不能失去覆盖。再在旁边
  加默认路径的断言（现在应当通过，或只剩 EXIF 之外的差异）。
- 断言的是修补（`无前缀` 的备注读得出、第 17 轮的 ImageUniqueID 补写）：默认路径上
  `无前缀` 会被自检挡回旧路，原断言应当不用改就绿；ImageUniqueID 的见证默认路径走照搬，
  原断言也应当绿，另加 `--no-raw-exif` 的一份让第 17 轮的补写路径继续有覆盖。
- 其余变红的：是真的退步，修代码，不改断言。

## 6. 验收标准

### 6.1 见证（端到端，`Tests/selftest.sh`）

给 `Tests/probe` 加一个「产物的 EXIF 与源是否逐字节相同」的子命令（输出相同/不同及位置）。

1. **整块照搬**：`读不出的标签` 的配方再加上 `GPS精度` 和一个 24 字节的 ImageUniqueID。默认路径：
   `✓ 元数据校验通过`；probe 报逐字节相同；`--delete-original` 删了源。`--no-raw-exif`：原来那几行
   差异一行不少。
2. **真实的 MakerNote**：`test_pic/IMG_1225.JPG`、`test_pic/P1130939.JPG` 的拷贝（沿用现有用例对
   `test_pic` 的用法，只读、用拷贝）。默认路径：probe 报逐字节相同；`{MakerCanon}/LensModel`
   从产物里读得出且等于源；IMG_1225 `✓ 元数据校验通过`；P1130939 只剩 `EOI 之后` 那一行。
   这两张带 IFD1 缩略图，逐字节相同就说明缩略图也过去了。
3. **方向**：Orientation 3、6、8（再加一个带镜像的）各一张。默认路径与 `--no-raw-exif` 的两个产物：
   `Orientation` 相同、解码像素相同。
4. **退回旧路**：`无前缀`、`只改IIM`。默认路径的产物与 `--no-raw-exif` 的产物**逐字节相同**，
   `--verify` 输出逐行相同；`-v` 里有没照搬的原因。
5. **XP 标签**：`只有XP`、`XP不同值` 默认路径通过；`--no-raw-exif` 照旧。
6. **增益图与辅助图**：`--aux depth --aux matte --aux gainmap`、`--iso-gainmap`、彩色增益图各一张。
   默认路径：probe 报 EXIF 逐字节相同；`--aux-diff` 对每种辅助图为 0；`--headroom` 与
   `--no-raw-exif` 的产物相同。
7. **没有死数据**：见证 1 的产物里，源 EXIF 里一段有辨识度的字节串（比如那个 24 字节的
   ImageUniqueID）恰好出现一次。

### 6.2 不变量（单测，手搭字节，不经过 ImageIO）

- 改写前后：旧长度之前的字节，除 `mdat` 长度字段、Exif 项的 `iloc` 偏移与长度、清零的旧范围
  之外逐字节相同；末尾是「原前缀 + 源 TIFF」；总长度 = 旧长度 + 新内容长度。
- 闸门每条一个反例，全部是「不换」而且输出等于输入：两个 Exif 项；没有 Exif 项；两段；构造方式
  1；最后一个盒子不是 `mdat`；旧范围与别的项重叠；旧范围不在 `mdat` 里；`iloc` 的 4 字节偏移
  放不下；32 位 `mdat` 长度放不下；前缀偏移离谱；各处长度、个数越界或自相矛盾；截断在任意位置。
- `mdat` 长度的三种写法（32 位、64 位、到文件末尾）各一个正例；`iloc` 版本 0、1、2 与
  offset_size 4、8 的正例。
- 抽出来的「不一致键集合」函数：一致→不一致算退步；不一致→换一个不一致的值不算；
  新出现且与源一致的键不算；新出现而源里没有的键算。

### 6.3 变异（每条亲眼看红，贴红的那几行）

| 变异 | 必须红在 |
|---|---|

### 6.4 零噪声与不退步

- `--no-raw-exif`：测试套件里所有夹具、`test_pic/` 两张，产物与 abc3b7b 逐字节相同，
  `--verify` 输出逐行相同。
- 默认路径：同一批输入，`--verify` 的差异行**只少不多**（按条目名算，不看值）；源里没有 EXIF
  的、被挡回旧路的，产物与 `--no-raw-exif` 逐字节相同。
- 照搬了的产物比 `--no-raw-exif` 的产物恰好大「4 + 6 + 源 TIFF 的字节数」。

### 6.5 健壮性

对产物字节做变异（截断到每一个长度、逐字节翻位至少覆盖整个 `meta` 盒）喂给改写函数：不崩、
不挂；结果要么等于输入，要么过得了 3.3。对源 JPEG 做同样的事走完整转换：不崩，产物打得开。

## 7. 文档（批 C）

`README.md`：命令行一节加 `--no-raw-exif`；`## 保留了哪些元数据`、`## --verify 到底比什么`、
`## 已知限制` 按做完后的行为改写，只写现在的行为。要写到的事实：

- EXIF 整块照搬，MakerNote、规范新标签、不合规范的写法、GPS 精度、内嵌缩略图都原样在产物里；
  哪些情形退回系统重写、退回后丢什么（就是现在「已知限制」里那些，挪到这个条件下面）。

- 没在 libheif、Windows、安卓的读取器上量过；读不了时用 `--no-raw-exif`。
