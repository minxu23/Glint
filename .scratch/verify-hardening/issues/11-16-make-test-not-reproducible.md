## 缺陷

同一棵工作树、同一个提交，`make test` 连跑：一次 `全部通过（13 轮，64 项断言）`，
紧接着一次红在五处（完整输出如下）。之后我又连跑两次，两次都过，至今**没能复现**。

```
  ✗ 没说明为何没删

       ✗ 续跑后全部完成（40 张）
       ✗ 续跑后全部完成
```

## 结论

**没有定位到根因，所以这条是 `needs-triage` 而不是 `resolved`。**

`续跑后全部完成（40 张）` 这个数字指向「上一轮的产物还在」——`$WORK` 那一次没被
擦干净。但 `rm -rf "$WORK"` 就在脚本第 60 行、跑在所有轮次之前，而且脚本没有
`set -e`，所以它要是失败了会一声不响地继续。

我没能复现，所以没有修任何东西。做的是把那个前提从「假设」变成「查过」：擦完
之后立刻数一遍 `$WORK` 里的文件，不为 0 就 `bail`。下次再撞上，至少会在
「前提不成立」这一步停住，而不是让后面几十条断言在测别的东西。

这条值得特别记一笔，因为它意味着：**这个会话里每一句「全部通过」，都只在
「那一次目录恰好是干净的」这个前提下成立**，而这个前提当时没人查。
