## 背景（交接方量到的，main = 8f786c8）

完整记录在 [`../encoder-variance/issues/01-product-size-varies.md`](../encoder-variance/issues/01-product-size-varies.md)，
要点：

- 平时走系统的硬件 HEVC 编码器。验收时撞上过一次：一批 33 张里有一张从 769 KB 变成 2.8 MB
  （`HEIF 比原图大 126%`）。那份产物是合法的 HEIC，仍是硬件编码器编的，只是整张图按相当于
  质量 0.98–0.99 的档位编了；这个大小用任何质量参数都编不出来，问题在 ImageIO / VideoToolbox
  里面。之后约 4.5 万次转换没再出现，没法按需触发。
- 另一件已查清的事：别的进程同时在编码、而本进程又在并发转多张时，一部分图会改由软件编码器
  编（大小不同，画质相当）。这不是缺陷，不用处理，但 README 要写。

## 要做的

### A. 变大就重编一次，取小的

`convert` 里，「编码 + EXIF 整块照搬」这一段得到临时产物之后：

- 产物比源大（判据与 `growthPercent` 相同：源的字节数 > 0 且产物字节数 > 源）时，把
  「编码 + 照搬」**原样再做一遍**，写到另一个临时文件。
- 第二份更小就用第二份；不更小（相等或更大）、或第二遍失败，就用第一份。没用上的那份删掉。
- 只重编一次。之后的流程（拷贝文件时间与扩展属性、换到目标位置、校验、变大提示、
  `--delete-original` 的判断）都针对留下来的那一份，逻辑不变。`ConversionReport` 里照搬的结果
  （`rawExif`）也取留下来那一份的。
- 产物不比源大时不重编，行为、产物、输出与现在逐字节、逐行相同。
- 预演（`--dry-run`）不受影响。

`-v` 时多一行，说明重编过以及两次的大小，例如
`    产物比原图大，重编了一次：2.8 MB → 769.4 KB（用了较小的一份）`；两次一样大时写明
「两次一样大」。不带 `-v` 不出这一行；图形界面不显示。

**为了能测**：异常没法按需触发，所以要给 `convert` 留一个接缝——把「编码」这一步做成带默认值的
参数（默认就是 `encodeHEIF`），单测注入一个假的编码步骤，让它第一次写出大的、第二次写出小的。
接缝只供测试注入，命令行和界面都用默认值；不要加环境变量或隐藏的命令行选项。

### B. 文档

`README.md` 的 `## 已知限制`（需要的话连同 `## 测试`）按做完后的行为写，只写现在的行为：

- 产物不是逐字节可复现的：平时走硬件编码器；别的进程同时在编码、本进程又在并发转多张时，
  一部分图改由软件编码器编，大小不同（实测同一张 788 KB 对 685 KB）、画质相当
  （PSNR 44.45 对 44.50 dB）。
- 硬件编码器偶尔会把一张图按高得多的质量编出来（见过一次，约 4.5 万次转换里一次），产物
  合法、只是大。产物比原图大时本工具重编一次、取小的那份；重编后仍比原图大的照旧提示，
  `--delete-original` 照旧保留源文件。原图本身很大、异常产物仍不超过原图时察觉不到。

## 验收标准

1. **单测（注入假的编码步骤）**，每条都要断言编码步骤被调用的次数、留下来的产物是哪一份
   （按内容或大小）、报告里的 `outBytes`：
   - 第一次比源大、第二次比源小 → 调用 2 次，留第二份，没有「变大」的备注。
   - 两次都比源大、第二次更小 → 调用 2 次，留第二份，仍有变大的备注。
   - 两次都比源大、第二次更大 → 调用 2 次，留第一份。
   - 两次一样大 → 调用 2 次，留第一份。
   - 第一次比源大、第二次失败 → 调用 2 次，留第一份，转换算成功。
   - 第一次不比源大 → 调用 1 次。
   - 第一次失败 → 调用 1 次，转换失败（不因为加了重编而多试一次）。
   - 目标目录里不留临时文件（每种情形都查）。
2. **端到端**：`变大.jpg`（`--noise` 夹具，转出来稳定地变大）加 `-v`：有重编那一行；现有的
   变大提示、不删源、汇总里的个数那几条断言不用改就绿。普通夹具加 `-v`：没有重编那一行。
3. **变异**（每条亲眼看红，贴红的那几行）：
   - 去掉重编 → 第 1 项前五条、第 2 项红；
   - 取大的那份（比较方向反了）→ 第 1 项红；
   - 不比源大也重编 → 第 1 项「调用 1 次」红；
   - 第二遍失败时把第一份也丢了 → 第 1 项红；
   - 没用上的那份不删 → 「不留临时文件」红。
4. **零噪声**：测试套件里所有夹具、`test_pic/` 两张，产物与 8f786c8 逐字节相同；不带 `-v` 的
   输出逐行相同；带 `-v` 的输出只在产物比原图大的那些图上多出重编那一行。比较期间不要并行跑
   别的转换或别的 `make test`。
5. 三个计数（现为 306 / 507 / 48）同步，增量与加的条数一致。

## 不做的

- 不去探测用的是哪个编码器，不解析码流。
- 不重试超过一次，不为「没变大但可能偏大」做任何事。
- 测试里逐字节比较的断言不加重试（量过，套件在并发下不假红）。
