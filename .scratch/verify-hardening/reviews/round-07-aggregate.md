### 判断题

**4. 三个 shape 解析器构成重复 switch（Repeated Switches + Duplicated Code）**
`isTimeOfDay`、`isDate` 与既有的 `normalizedOffset(token:precededBy:)` 形状完全同构：`switch count` → 查分隔符位 → 攒 `digits` → `Int(String(...))` 验范围；三条 doc 注释还各自重写了一遍「宽度前提在本函数内成立」这同一段推理。值得抽一个 `match(_ chars:, 模板:, 字段范围:)`（模板如 `"dd:dd:dd"` / `"dddddd"` / `"dddd-dd-dd"`），三处共用一张模板表。

**下标安全这一关是过的**：每个 guard 的前提都在本函数内由 `switch t.count` / `switch d.count` 就地建立，不依赖调用方的 `for width in [8, 6, 5, 4]`；`digits[4...5]` 被前面的 `if digits.count == 4 { return true }` 挡住，无越界路径。

一处名实不符：`allSatisfy(\.isNumber)` 会放过全角及其他数系的数字字符，目前靠后续 `Int(String(...))` 返回 nil 兜住——想让这个证人名实相符，写成 `isASCII && isNumber`。（`splitIIMTime` 的 `chars[0..<6].allSatisfy(\.isNumber)` 同理，是既有问题，本轮在新函数里复制了这个写法。）

删掉 `UTCOffset.canBegin` 并内联是合理的（原方法的 doc 注释自己就承认它不是单一事实来源，典型 Middle Man）。

**5. `EXPECTED_PASSES` 用精确值会在真失败时制造第二条假失败**
断言失败走 `fail`，`PASSED` 不自增，于是任何一条真实失败都会额外打印「通过 N 项，预期 58 项——有断言没有执行」，并给出误导性的原因。应比 `PASSED + FAILED` 的总数，或在 `FAILED > 0` 时跳过这条检查。

**6. `EXPECTED_ROUNDS` 几乎被 `EXPECTED_PASSES` 包含**（整轮消失必然带走它名下的 pass），却要维护第二个魔数；只有「轮次标题还在、但整轮一条断言都不剩」这种边角才由它独占。另外第 2 轮的 pass 数由 `KEYS` 列表的行数决定，改 `KEYS` 要跑到文件顶部改 `EXPECTED_PASSES`（小 Shotgun Surgery + 魔数）。

**7. trap 注释略超实际**：脚本只有 `set -uo pipefail`（无 `-e`），现存的提前 `exit` 全部走 `bail`。所以 trap 实际兜住的是 `set -u` 的未定义变量中止与信号，不是注释说的那种情形。守卫便宜、可留，措辞该收一收。

**8. 两处脆弱引用**：`Tests/probe-src/main.swift:43` 硬写 `Converter.swift:49 的 ?? [:]`——今天对得上，但行号必漂，改引函数名；`Tests/selftest.sh:60` 的 `2>/dev/null` 吞掉 stderr，Makefile 真出语法错时会被报成「问不到产物清单」，掩盖真实原因。

## Spec

### (c) 看着实现了但实现错了 —— 一条仍在静默放过的路

**`±` 侧比新收紧的 Z 侧明显更松，两侧已不是"同一把尺子"。**
Spec（README 第 130 行起）：「读偏移时三种形状（`±HHMM`、`±HH:MM`、`…Z`）都**锚定在末尾逐字符核对**」「读成一个**合法值**比读不出更坏，因为连差异都不剩」。

`normalizedOffset(token:precededBy:)`（`MetadataDiff.swift:333`）对前文只有一句 `if let previous, !previous.isNumber { return nil }` —— 只要符号前一位是数字，前面是什么散文都收。实测：

```
镜头型号RF50mm1+0800 -> +0800     （Z 孪生兄弟 镜头型号RF50mm1Z 本轮被明确拒）
+08:00 (approx)5+0800 -> +0800   （+08:00 (approx)5Z 被拒）
ISO100+0800 / abc1+0800 -> +0800
9999-99-99T18:42:07+08:00 -> +0800（9999-99-99T18:42:07Z 被拒）
2024-0915+0800 / 20240915+0800 -> +0800
```

这是**目标侧**读取器，一松 `offsetSurvives` 就把"偏移其实已经丢了"读成"还在"。单测只有 `("abc+0800","")`，钉住的是"前一位非数字"那一半；`abc1+0800` 这一半无证人。建议 `±` 侧也复用 `terminatesTime` 那套锚定。

Z 侧本身未发现误拒真实写法（基本/扩展格式、分钟精度、`.`/`,` 小数秒、空格分隔、闰秒都认；仅小时精度 `…T18Z` 被拒，无写入器产出，可接受）。
