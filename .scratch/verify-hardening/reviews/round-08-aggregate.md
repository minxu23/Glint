### 判断题（按严重度）

**1. 注释说大话（本轮又一例，`MetadataDiff.swift:205-207`）**

> `连「宽度前提在本函数内成立」那句注释都重复了三遍。现在只有这里需要那句话`

同一 diff 的 `normalizedOffset` 里仍留着「宽度前提在本函数内成立，不寄托于调用方的 `for width in [5, 6]`」（355 行）。说"只有这里需要"当场被自己推翻。另外「下面所有下标都由 template 与 value 的长度在本函数内对齐」也不准确——函数内其实是逐处 `i < value.count` 显式守卫，并没有任何长度对齐前提。

**2. 模板是陷阱：`"dddddd"` vs `"dd|dd|dd"`（Primitive Obsession）**
字段边界只由 `|` 决定，而 `d` 的个数在视觉上不传达任何分段信息。`"dddd-dd-dd"`（3 段）和 `"dddddd"`（1 段）字面高度相似、语义天差地别，纯靠文档注释撑着。更坏的是把形状编成 String 后编译期丢失了元数——三个调用点不得不各自在运行时补 `parts.count >= 2` / `== 3` / `== 2`，这正是类型本该做的事。建议把模板做成小类型（枚举或 `[Field]`），`|` 这种不可见分隔符就不必存在。

**3. `"dddddd"` 这一处不诚实**
`splitIIMTime`（182 行）只判 `!= nil`、丢弃返回值，`"dd|dd|dd"` 行为完全等价；`"d*"`（319 行）同理。6 个调用点里只有 4 个真用返回值。单测 `expectFields("184207", "dddddd", [184207], "IIM 时间整段当一个字段")` 钉住的是一个没人消费的语义——这条是 Speculative Generality 的真正落点，不是整个函数（10 处模板复用、替掉三段 `switch count`，抽取本身划得来）。

**4. `isASCII` 冗余条件 + 四行自白**
注释与测试都承认"去掉照样过"。留一个自知无法被用例钉住的条件，加四行解释它为什么留着，成本高于它表达的意图。

**5. `Tests/selftest.sh` 的两段守卫是 Duplicated Code**
`unit_n` / `gui_n` 两块形状逐字相同：`grep -cE '✓|✗'` → 比常量 → `pass`/`fail` 同模板文案 + 同一句注释。应抽成 `expect_count 名称 输出 期望`，一处定义两处调用。顺带：`grep -c` 数的是**行**数，一行含两个 ✓ 就少算。

**6. `EXPECTED_PASSES` 已是 Mysterious Name**
它现在比的是 `executed=$((PASSED + FAILED))`，即"执行条数"，名字和三处文案却还在说 passes。改名 `EXPECTED_ASSERTIONS`。

**7. 四常量里 `EXPECTED_ROUNDS` 基本被吞掉**
整轮消失必然让 `executed` 也对不上，`EXPECTED_ROUNDS=12` 的独立信息量趋近于零，却要跟着维护。`EXPECTED_UNIT`/`EXPECTED_GUI` 与 `EXPECTED_PASSES` 不重叠（子套件被压成 1 个 pass，确实看不见缩水），该留；建议删 `EXPECTED_ROUNDS`，从四个减到三个。

### (c) 实现看起来不对：`±` 侧新引入了一处真实误拒

README：「找的范围是 `{Exif}/OffsetTime*`、`XMP/exif:OffsetTime*`，以及**该键自己的那两个等价时间戳**（偏移可以长在值里，如 `2024-09-15T18:42:07+08:00`）」，而同一节又写明「EXIF 写 `2024:09:15 18:42:07`」。

`isDate` 的模板只有 `"dddd-dd-dd"` 和 `"dddd|dd|dd"`，没有 EXIF 自己的冒号日期 `YYYY:MM:DD`。实测：

- `2024:09:15 18:42:07+08:00` → `nil`（旧版"符号前一位是数字"读成 `+0800`）
- `2024:09:15 18:42:07Z` → `nil`

`offsetSurvives` 的搜索范围里恰好就包含 `{Exif}/DateTimeOriginal`（`alternatives`）。所以目标侧若把偏移长在 DateTimeOriginal 的值里，本轮之后会把「偏移还在」误报成「丢了」。方向上是多报（符合「宁可多报一条」），但它让 README 点名的两个等价时间戳之一变成读不出来，且**无任何用例覆盖**。建议给 `isDate` 加 `"dddd:dd:dd"`，并补一条用例。

其余真实写法全部仍能认（已实测）：`+08:00`、`+0800`、`-00:00`→`-0000`、`+05:45`、`+13:45`、`2024-09-15T18:42:07.42+08:00`（ImageIO 实际写法）、`,420` 逗号小数秒、`20240915T184207+0800`、`2024-09-15T18:42+08:00`、`184207+08:00`、空格分隔 `2024-09-15 18:42:07+08:00`；`+14:30` 仍拒。`numericFields` 未见回归：`splitIIMTime("184207+08:00")`→`(184207, +0800)`、`000000+0000`→`(000000, +0000)`，前导零归一化正确；十条目标反例全部已拒。

## 我核过的部分

**Spec (c) 成立，这是本轮唯一的行为缺陷**，实测：

```
2024:09:15 18:42:07+08:00     -> nil     ← EXIF 自己的日期格式
2024:09:15 18:42:07Z          -> nil
2024-09-15T18:42:07+08:00     -> +0800   ← ISO 格式，对照
```

讽刺的地方在于：被拒的恰恰是这个项目读得最多的格式。`{Exif}/DateTimeOriginal` 和 `{TIFF}/DateTime` 在真实产物里就是 `2024:09:15 18:42:07`（我刚探过夹具的 HEIC，两个键都是这个形状）。我做"真实写法必须继续认"那一组验证时，一条都没放 EXIF 的冒号日期——因为我是从 ISO 8601 规范出发列的全集，而 EXIF 的日期**不是** ISO 8601。上一轮我还在总结里说"从规范定义出发列全集"是解法，这轮就被同一个思路坑了：我列全了一个规范的全集，漏掉了另一个规范。

可达性上我要给它打个折：EXIF 规范本身规定 `DateTimeOriginal` 不带偏移（偏移住在 `OffsetTimeOriginal`），所以要踩到这条得有个不合规的写入器把偏移塞进值里。方向也是多报而非静默放过。但修它只要给 `isDate` 加一个模板，而且 README 点名了这个等价键，不该让它读不出来。

**闰秒**那条我也量了，`±` 侧其实是认的（`23:59:60+08:00` → `+0800`），只是没有用例——所以是覆盖缺口而非行为缺陷。

**Standards 第 7 条我原本不同意，量完是它对。** 每轮断言数 `0:2 1:2 2:16 3:2 4:5 4b:9 5:5 6:3 7:8 7b:3 8:2 9:3`，没有零断言的轮，所以删任何一轮 `executed` 必然对不上。我上一轮拿"标题绕过 `round()`"当它的证人，但那种改动不破坏任何覆盖；而真该挡的"新增一轮却用 `echo`"它反而挡不住。

**Spec (b)1 我不认**：那条用例守的是"全角数字不算数字"这个**行为**，不是守 `isASCII` 那个条件。行为真坏掉（比如改成用宽松的数字解析）它会红，不是永不会红。注释里我已经写明了这个区别。不过 Standards 第 4 条的成本论我接受——既然 `Int()` 已经是真守卫，留一个冗余条件加四行自白不如删掉条件、留一行说明。
