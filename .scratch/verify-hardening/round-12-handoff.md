# 第 12 轮交接稿：给实现者

这份文件是自足的：你不需要读产生它的那段对话。审查由 Fable 5.2 做（两份原文在
`reviews/round-12-standards.md`、`reviews/round-12-spec.md`），下面每一条"已复现"
的现象都由交接方在独立拷贝里重新量过，不是转述。用户已逐条划过线：下面列的都是
**决定要做的**，末尾"已拒绝"里的不要做。

## 0. 先读这一节

**项目**：macOS 上把 JPEG 转 HEIF 并保留元数据，Swift + ImageIO + AppKit，零第三方
依赖，只用 Command Line Tools 构建。`make test` 是唯一的测试入口。注释和输出是中文。

**长期要求**（`spec.md`）：(1) `--verify` 绝不静默放过真实的元数据丢失，宁可多报；
(2) 功能坏了测试必须失败，不可能变红的断言等于没有；(3) 源侧与目标侧用同一把尺子。

**这个项目为什么需要这份交接稿**：前十一轮"审查→全修"效率很低。复盘出的原因是你
要避开的东西——

1. **修的是实例不是类。** 审查举一个反例就补一个反例。本稿每条都按"类"写，修的时候
   把同形状的所有位置一起处理。
2. **注释断言了没人检查的事实。**"只有这里""恒真""因为那里有个 switch"这类话连续
   四轮被代码推翻。**不要写叙述历史的注释**（"上一版曾经…""第 N 轮…"）。注释只写
   现在时的不变量；来历写进提交信息。
3. **守卫因为错误的原因通过。** 所以下面每条都带"验证方案"：一个变异，和它必须让哪条
   断言变红。**没有做过这个变异、没亲眼看到红，就不算修完。**

**工作规则**

- 只在你自己的 worktree 里工作。**任何时候不要并发跑两个 `make test`**——它们共用
  `Tests/.work` 会互踩（这正是下面 L1 要修的，修好之前尤其要小心）。
- **mtime 陷阱**：make 的时间戳粒度是 1 秒。同一秒内"还原 → 变异 → make"不会重建，
  变异会假绿。每次变异后确认 make 的输出里真有 `swiftc` 行；单测可用
  `make -B Tests/unit-test`。（`make -B test` 目前会误报，见 T8。）
- **看退出状态，不要从输出里读成功。** 替换文本用"断言锚点恰好出现一次"的方式做，
  锚点没匹配就停，不要让后面的测试在没改过的代码上打印"全过"。
- 改了断言条数要同步 `Tests/selftest.sh` 顶部的 `EXPECTED_ASSERTIONS` /
  `EXPECTED_UNIT` / `EXPECTED_GUI`，并且确认增量和你加的条数一致。
- 行为变了就同步 `README.md`（`## --verify 到底比什么`、`## 已知限制`、
  `## 保留了哪些元数据`）。README 是规范性的，它和代码不一致本身就是缺陷。
- **范围**：只做本稿列的条目。途中发现别的问题，写进交付报告的"未处理的发现"，
  不要修。不要新增给文档或账本用的守卫。除批 D 明确要求的之外不要动 `.scratch/`。
- 测试必须自足：不能依赖 Python、不能依赖 `round-12-repro/` 里的脚本。那个目录只是
  参考（样本怎么造）。造样本用仓库里已有的 Swift 小工具（`Tests/fixture.swift`、
  `Tests/mangle/`）扩展。

**分批**：A → B → C → D，**一次只做一批**，做完提交、交报告、停下等验收。

**每批的交付报告**要有：提交 SHA；逐条"改了什么（文件）/ 做了哪个变异 / 红在哪条
（贴那几行输出）"；和本稿不一致的地方及理由；未处理的发现。

## 批 A：先让测试可信

后面所有验证都靠测试，所以先修测试自己。

### L1 并发的 `make test` 互踩

- **现象（已复现）**：单跑一轮约 11 秒。两个 `make test` 在这 11 秒内重叠就互相破坏，
  因为都用 `Tests/.work`。错开 1 秒、2 秒、6 秒启动都会红，错开 4 秒碰巧都过。症状
  每次不同（`续跑后全部完成（40 张）`、`无法构造测试样本`、`界面没有产出 .heic`…）。
- **修改方向**：每次运行用独立的工作目录（`mktemp -d`），成功结束时清掉，失败时留着
  供诊断并打印路径。`Makefile` 的 `clean` 和 `.gitignore` 跟着对齐。删掉脚本里
  "擦完之后数文件，不为 0 就 bail"那一段——它防的是一个错的假设（竞争发生在擦完
  之后，实测它一次都没响过）。
- **验证方案**：产物建好后，分别错开 1、2、4、6 秒并发启动两个 `make test`，八次运行
  全部 `全部通过`。修之前同样的实验在 1、2、6 秒处会红。

### T2 两侧同空也算相等

- **现象（已复现）**：把写访达备注的那行 `xattr -w …kMDItemFinderComment…` 删掉，
  仍打印 `✓ 访达备注保留`——两边都读出空串。另外那条断言用 `head -c 4` 只比了前 4
  字节。同一形状的还有：
  - "状态说明不计入差异条数"：`n1`、`n2` 都是从产品输出里 `grep -oE '发现 [0-9]+ 处差异'`
    得到的，产品文案一改两边同为空，照样相等；
  - 文件层那几条用 `stat` 比对的；图形界面端到端那几条没有哨兵检查的；
  - 第 2 轮字段清单只挡 `<无>`，不挡空串和 `<无法读取>`；
  - 否定式断言（"没有…""不该…"）前面没有确认命令真的跑了：`$BIN` 直接崩溃也会 ✓。
- **修改方向**：一个比较助手，期望侧为空或为哨兵值（`<无>`、`<无法读取>`）时判失败。
  否定式断言之前先断言命令确实执行并成功。**把脚本里所有这个形状的断言扫一遍**，
  不要只改上面点名的。访达备注比全值。
- **验证方案**：(a) 删掉 `xattr -w` 那行 → 红；(b) 把产品里"发现 N 处差异"的文案改掉
  → 红；(c) 把某条否定式断言的命令换成 `false` → 红。

### T4 循环里 fail、循环后无条件 pass

- **现象（已读代码确认）**：`7b. 偏移只靠 XMP 承载` 那一轮里，探 `OffsetTime*` 的三层
  `for` 循环在不满足时 `fail`，出循环后无条件 `pass "该样本里确实没有任何 OffsetTime*…"`。
  前提不成立时会同时出现若干 ✗ 和这条 ✓，并让断言总数对不上，于是末尾追加一条
  "执行了 N 项，预期 M 项"的误诊。
- **修改方向**：循环里只计数，出循环后发恰好一条 pass 或 fail。
- **验证方案**：把这一轮的样本换成默认夹具（带 `OffsetTimeOriginal`）→ 这条检查恰好
  1 条 ✗，且**没有**断言条数误诊。

### T8 `make -B test` 误报

- **现象（已复现）**：`make -B test` 输出"jpeg2heif 不是当前源码建出来的"。新鲜度
  检查里的 `make -q` 继承了外层的 `MAKEFLAGS`（里面带着 `-B`）。
- **修改方向**：问询时清掉继承来的 make 标志。
- **验证方案**：`make -B test` 全过；改一个源文件后直接 `bash Tests/selftest.sh`

### T1 `splitIIMTime` 的守卫没有独占证人

- **现象（已复现）**：`MetadataDiff.swift` 里 `splitIIMTime` 有三道守卫，注释写"三个
  条件缺一不可……三个证人各自只被其中一道拦住"。逐一变异：
  - 删 `chars[6] == "+" || chars[6] == "-" || chars[6] == "Z"` → 单测 220/220 仍绿，
    而 `184207.555Z` 从"不拆"变成 `("184207", +0000)`：小数秒被静默截掉。这才是那道
    守卫真正独占的证人，**没有用例**。
  - 删 `isAllDigits(Array(chars[0..<6]))` → 仍绿。
  - 总长条件放宽成 `>= 7` → 仍绿，点名证人 `184207+12+0800` 照样被拒。
  - 注释里点名的证人 `1842071+0800`、`184207+12+0800` 现在都是被 `UTCOffset` 自己拦下
    的，和这三道守卫无关（它们在早期是真证人，后来 `UTCOffset` 收紧把外层架空了）。
  - 同类：`isTimeOfDay` 里 `parts.count >= 2` 恒真。
- **修改方向**：每道守卫都要满足"删掉它，某条点名用例变红"；满足不了的就删掉守卫，
  而不是给它编理由。补 `184207.555Z` 用例。注释只列你亲手验证过的证人。
- **验证方案**：删 `chars[6]` 那道 → `184207.555Z` 用例红。被你删除的守卫，用
  `round-12-repro/fuzz-splitIIMTime.swift` 那种随机对拍证明删除前后零差异（把结果数字
  写进报告）。

### S4 `metadataDiff` 的主循环没有证人

- **现象（已复现）**：下面三处变异各自重建后 `make test` 仍 67/67 绿——
  - `if equivalentCarries(key: k, value: v, in: after) { continue }` 改成
    `if equivalentKeys[k] != nil { continue }`（README 明令禁止的"等价字段存在就放过"）；
  - `} else if !valuesMatch(v, after[k]!) {` 改成 `} else if false {`（整条"变化"分支失效）；
  - `if !makerNoteLost.isEmpty {` 改成 `if false {`（相机照片丢 MakerNote 不再报）。
  也就是说，被反复加固的那个解析器可以整个从 `--verify` 上摘掉而测试不红。
- **修改方向**：把"两个键空间 → 差异列表"抽成纯函数，单测逐分支喂手搭字典。
- **验证方案**：至少四个用例——值变化被报；IIM 日期键在、等价字段也在但值不同 → 报；
  `{MakerCanon}/x` 丢失 → 出现汇总行；易变键被跳过。另加一条端到端：
  `test_pic/IMG_1225.JPG`（**先拷贝再转，别动原件**）校验输出含 `MakerNote`，
  `--delete-original` 不删源。上面三处变异各自必须变红。

### T7 `out` 变量跨断言复用

- **现象**：第 7 轮给 `out` 赋值后隔了几条断言才读；7b 轮又复用 `out`，靠三行注释解释

## 批 B：校验器的静默放过

### S1 源侧读的是 ImageIO"调和"后的视图

- **现象（已复现）**：`metadataKeySpace` 对源文件读的是 ImageIO 的属性视图，而 ImageIO
  会把 EXIF、IIM、XMP 里的时间字段互相调和。实验：
  `fixture --no-exif-offset` 造的图里，EXIF 时间串 `2024:09:15 18:42:07` 出现 3 次，
  IIM `184207+0800` 1 次，XMP 里 `+08:00` 1 次。把那 3 处等长改成 `…18:42:08` 之后：

  | 键 | 原样 | 改后（ImageIO 视图） |
  |---|---|---|
  | `{IPTC}/TimeCreated` | `184207+0800` | `184208` |
  | `XMP/photoshop:DateCreated` | `2024-09-15T18:42:07.42+08:00` | `2024-09-15T18:42:08.42` |

  源文件字节里的两个偏移都还在，视图里都没了。转换结果：`✓ 元数据校验通过`，
  `--delete-original` 删了源，HEIC 里 `+08:00` 和 `+0800` 各出现 0 次。
  审查方还报了反向的一例（未由交接方复现）：默认夹具只把 IIM 改成 `104207+0000`，
  HEIC 的 `DateTimeOriginal` 变成 `10:42:07` 而 `OffsetTimeOriginal` 仍是 `+08:00`，照样通过。
- **方向与可达性**：静默放过。任何"只改过 EXIF 时间"的照片都会中（例如导出后用
  `exiftool -AllDates` 调时间）。
- **修改方向**：对 ImageIO 会调和的字段，源侧的真相取自源文件的原始字节——
  EXIF 的 `0x9003/0x9004/0x0132` 和 `0x9010–0x9012`，IIM 的 `2:55/2:60/2:62/2:63`，
  XMP 包里的日期。`ExifReader.swift` 已经有 IFD 遍历可以复用。判据是"原始字节里的
  时间和偏移信息，在目标里按现有的等价规则找得到"，**不是**"原始值与视图逐字符相等"
  ——后者会误报：一致的夹具里视图也会给 XMP 时间补上 `.42` 小数秒。实现方式你定，
  用下面的见证和零噪声要求约束。
- **必须同时做 S8a**：`carriesSameValue` 现在是"只留数字后做子串包含"，实测
  `("091518", "2024:09:15 18:42:07")` 为 true（跨日期和时间凑出来的），
  `("074208", "2024-09-15T18:42:07.42+08:00")` 为 true（靠小数秒和偏移的数字凑的），
  `("٢٣", "x٢٣")` 为 true（`isNumber` 留下了非 ASCII 数字）。原来因为视图总是自洽而
  不可达，原始值入场后就可达了。改成按位置比较（日期位、时间位分开），只认 ASCII 数字。
- **验证方案**：
  - 上表那张图：校验必须报出差异，`--delete-original` 必须保留源；
  - 反向那张（IIM 改 `104207+0000`）：同样必须报；
  - 上面三组 `carriesSameValue` 输入全部期望 false，现有为 true 的用例保持 true；
  - **零噪声**：默认夹具、`--no-exif-offset` 夹具、`--lossy` 夹具、`test_pic/` 两张真实
    照片的校验输出，与修改前相比不得多出任何一行（把前后输出贴进报告）；
  - 变异：去掉原始字节那一路 → 前两条见证变红。

### S2 ImageIO 看不见的数据整段丢失

- **现象（COM 段与尾部数据已复现；APP11 与 XP 标签为审查方实测）**：以下各自
  `✓ 校验通过`、`--delete-original` 删源、HEIC 里找不到内容——
  JPEG COM 段里的备注；APP11 段（C2PA 用它）；EOI 之后的尾部数据（安卓动态照片把
  视频放这里）；EXIF IFD0 的 `XPComment/XPKeywords/XPTitle`（`0x9C9B–0x9C9E`）和
  `Rating`（`0x4746`）。`ExifReader.swift` 的文件头注释自己写着"连 --verify 也发现
  不了，因为它比的也是 ImageIO 的视角"，却只修了 UserComment 这一个实例。
- **方向与可达性**：静默放过。Windows 资源管理器写的备注和标记、动态照片、带 C2PA 的图。
- **修改方向**：扫一遍源 JPEG 的段结构，做一份"ImageIO 不会搬的东西"的清单：COM 段、
  不认识的 APPn、EOI 之后的字节，各报一条"源里有、搬不走"。XP 标签和 Rating
  **这次不做检测**，只写进 README 的"已知限制"。
- **注意**：真实照片的 EOI 之后可能本来就有东西（多图格式把增益图、深度图放在主图
  之后）。这些确实会丢，现有逻辑已经通过 `{FileContents}` 报了一部分。不要重复报，
  也不要漏报——对 `test_pic/` 两张真实照片，把新旧校验输出逐行对比贴进报告，
  新增的每一行都要说明它对应的是哪段真实数据。
- **验证方案**：COM、APP11、尾部数据三张样本各自报差异且不删源；变异：让清单函数
  返回空 → 三条都红。

### S6 CMYK 的 ICC 被悄悄换掉

- **现象（已读代码确认；转换结果为审查方实测）**：`volatileKeys` 里有
  `kCGImagePropertyProfileName` 和 `kCGImagePropertyColorModel`。CMYK JPEG 转换后
  `Generic CMYK Profile → sRGB IEC61966-2.1`、`CMYK → RGB`，校验通过并删源。README
  的忽略清单里没有这两个键，而且写着"ICC 色彩描述文件…一并保留"。
- **修改方向**：把这两个键移出 `volatileKeys`。审查方实测 sRGB、P3、AdobeRGB、
  ProPhoto、BT.2020、灰度和两张真实照片都不会因此多报。
- **验证方案**：CMYK 样本报出这 2 条；单测里这两个键的"应被忽略"断言翻成"不应被
  忽略"；默认夹具和两张真实照片零新增。

### S3 界面没校验却显示"校验无差异"

- **现象（已读代码确认）**：`Sources/GUI/Model.swift` 的 `detailText` 里
  `if issues.isEmpty && tagCount > 0 { parts.append("校验无差异") }`，不看有没有开校验。
  根源在 `Converter.swift` 的 `ConversionReport.issues`，它的注释自己写着"空表示没有
  差异（或没开校验）"——一个值两个意思。用户取消勾选"转换后校验元数据"后，必然丢
  数据的图也显示"校验无差异"。
- **修改方向**：把校验结果改成三态（未校验 / 通过 / 有差异），让下游在类型上就无法
  把"没校验"当成"通过"。命令行和界面所有读 `issues` 的地方一起改。
- **验证方案**：模型层测试里 `verify = false` 配 `--lossy` 夹具，`detailText` 不得
  含"校验无差异"；把判据改回原样 → 红。

## 批 C：XMP"原样搬运"（A、B 验收之后再做）

### S5 `kCGImageDestinationMetadata` 那两行是空操作

- **现象（已复现）**：`Converter.swift` 里
  `destProps[kCGImageDestinationMetadata] = xmp` 和 `…MergeMetadata] = true` 两行删掉后
  `make test` 仍全过。审查方实测：它们对 `CGImageDestinationAddImageFromSource` 不起
  作用，富 XMP 样本 45 个键丢 12 个（`xmp:Label`、`lr:hierarchicalSubject`、`dc:title`
  的其它语言、人脸区域的 `Name`、自定义命名空间、`xmpMM:*`）。README 写的是"关键词、
  评级、版权、人脸区域等，原样搬运"。
- **方向**：多报（校验会报出来），但功能本身没实现。Lightroom 导出的文件都会中。
- **修改方向**：改走 `CGImageDestinationAddImageAndMetadata`。审查方实测富 XMP 样本和
  夹具零差异、两张真实照片只剩 MakerNote。**但 UserComment 修补那条路要跟着改走
  `CGImageMetadata`，这一步没人测过**——它是本稿里唯一会改变产物内容的一条，回归
  风险最高。动手前先确认：ICC、像素、增益图等在新路径下是否仍然保留（原路径选
  `AddImageFromSource` 的理由就是它连带保留这些）。保不住就停下来报告，不要硬改。

  → 红；第 6 轮（不合规范的 UserComment）仍然全过；`test_pic/` 两张真实照片的校验

## 批 D：纯删减（最后做，因为前面会动同一批区域）

### T5 数字和序数类的注释失实

- **现象（已确认）**：`README.md` 写"有三类差异会被有意忽略"，下面列了四条；
  `docs/agents/issue-tracker.md` 写 "ten rounds so far"；`Tests/selftest.sh` 的注释
  引用了已不存在的 `EXPECTED_PASSES`，以及"三种/第二种/第四种走法"互相对不上；
  `Tests/probe-src/main.swift` 写"任何能读的图都至少有 PixelWidth 这类键"，而
  `imageProperties` 实际把它删了（实测 probe 查 `PixelWidth` 返回 `<无>`）。
- **修改方向**：**删掉数字和序数，不是把它们改对**——改对了下次还会过期。
- **验证方案**：
  `grep -nE '三类|rounds so far|EXPECTED_PASSES|第[二四]种|PixelWidth 这类'` 在这四个
  文件里为空。

### T6 叙述历史的注释

- **现象**：`MetadataDiff.swift` 注释 272 行、代码 293 行，其中约 30 行在讲"上一版/
  曾经/第 N 轮"；`selftest.sh` 的注释从 43 行涨到 130 行。上面 T1、T5 的失实全出在
  这类段落里。还有事实写错地方的：`carriesSameValue` 用什么过滤数字，写在 220 行外
  `numericFields` 的注释里，它自己的文档只字未提。
- **修改方向**：注释只留现在时的不变量，以及守它的用例名。历史一律删（提交记录里
  都有）。事实挪到它描述的代码旁边。**这是纯删减，不改任何行为。**
- **验证方案**：这两个文件 `grep -cE '上一版|原先|曾经|以前|第.{1,2}轮'` 归零；
  三个 `EXPECTED_*` 一个都不变；`make test` 全过。

### 删掉 selftest 第 10 轮（账本守卫）

- **背景**：`.scratch/verify-hardening/` 是前十一轮的审查账本，现已冻结为存档，
  不再新增条目。`Tests/selftest.sh` 的"10. 审查账本…"那一轮守的是这份账本的格式，
  占脚本约四分之一，让产品自检依赖 git 历史，而且审查方实测它仍可被绕过。用户的
  决定是**不加强它，直接删**。
- **修改方向**：删掉整个第 10 轮；同步 `EXPECTED_ASSERTIONS`；`docs/agents/issue-tracker.md`
  的 `## Review-round efforts` 一节和 `spec.md` 里提到"selftest 检查这件事"的句子
  改成如实陈述：账本冻结于第 11 轮，是存档，不再有守卫。
- **验证方案**：`make test` 全过且轮数减一；`grep -n '审查账本\|verify-hardening' Tests/selftest.sh` 为空。
