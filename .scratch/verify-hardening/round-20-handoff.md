## 1. 目标

第 18 轮的 EXIF 整块照搬有一类照片不受益：`UserComment` 缺字符集头的（不少安卓机型直接塞裸
UTF-8，ImageIO 当它不存在）。系统重写那条路会把备注修补成 ImageIO 读得出的写法；整块照搬
是原样过去，ImageIO 读不出，被「视图不退步」的自检挡回系统重写——于是这类照片照旧丢
MakerNote、GPS 精度等。相册里加过备注的照片恰恰是这一类。

这一轮：这类照片也照搬，**在照搬的块上只改备注这一条**，改成 ImageIO 读得出的写法。

## 2. 交接方量到的事实（main = f1ced2c）

量具 [`round-20-repro/tiffuc.py`](round-20-repro/tiffuc.py)（依赖 `round-18-repro/exifswap.py`），
只供参考写法，测试不得依赖。四个源：大端（MM）、小端（II）各配中文备注和纯 ASCII 备注，
都是没有字符集头的裸 UTF-8。

### 2.1 现状

四张都是 `EXIF 没有照搬：照搬后 {Exif}/UserComment 会读不出`，校验通过（走的系统重写）。

### 2.2 改法：新值接在 TIFF 块末尾，只改 0x9286 那一条的类型、个数、偏移

源的 TIFF 字节原样不动（旧的备注字节也留在原处，只是没人引用了），块长为奇数时先补一个 0，
新值接在后面，ExifIFD 里 0x9286 条目的 type 改成 7、count 改成新值的长度、offset 指向新值。
把这样的块照搬进产物，ImageIO 从 HEIC（和 JPEG）里读得出备注；别的标签、MakerNote 不受影响
（它们的偏移没动）。

### 2.3 ImageIO 读 `UNICODE` 备注的规则：有 BOM 认 BOM，没有就一律当大端

| 新值的写法 | MM 的块 | II 的块 |
|---|---|---|
| `UNICODE\0` + UTF-16（与 TIFF 同字节序，无 BOM） | 读对 | **乱码** |
| `UNICODE\0` + UTF-16（与 TIFF 反字节序，无 BOM） | 乱码 | 读对 |
| `UNICODE\0` + BOM + UTF-16（与 TIFF 同字节序） | 读对 | 读对 |
| `ASCII\0\0\0` + UTF-8 字节，文本含非 ASCII | 乱码（按 Latin-1） | 乱码 |
| `ASCII\0\0\0` + 文本，纯 ASCII | 读对 | 读对 |
| 8 个 0 + UTF-8 | 读不出 | 读不出 |

HEIC 和 JPEG 两种容器读出来一样。ImageIO 读回时去掉 BOM。exiftool 六种都读得对。

### 2.4 现行校验对这样的产物

`src → 「照搬 + 改写备注」的产物`，四张都恰好只有一行：
`变化 EXIF 数据块：照搬过来的 EXIF 与源不一致（831 字节 → 872 字节，第 320 个字节起不同）`
（第 18 轮的 4.2 那条）。键空间比对、原始清点都过——备注的值在视图里与源侧修补后的值相同。

## 3. 设计（已定）

### 3.1 什么时候改写

与系统重写那条路的修补同一个条件（`repairedProperties`）：ImageIO 在源里读不出 `UserComment`
（去掉填充后为空），而 `rawExifUserComment` 解得出文本 T。此外还要：

- ExifIFD 里**恰好一个** 0x9286 条目，条目本身在块内（值内联在条目里的也算，count ≤ 4）。
- 拿不准就不改写：照原样照搬，由「视图不退步」的自检决定去留（也就是现在的行为）。

不满足改写条件的照片，产物必须与 f1ced2c 逐字节相同。

### 3.2 改写成什么

纯函数：进源的 TIFF 字节和文本 T，出新的 TIFF 字节（或不改写）。

- T 全是 ASCII：`ASCII\0\0\0` + T 的字节。
- 否则：`UNICODE\0` + BOM + T 的 UTF-16，字节序与 TIFF 头相同（BOM 也按这个字节序写）。
- 块长为奇数先补一个 0；新值接在后面；0x9286 条目的 type = 7（UNDEFINED）、count = 新值长度、
  offset = 新值的位置，都按块的字节序写。**除这 10 个字节（条目的 type、count、offset）以外，
  源 TIFF 的每一个字节都不动。**

不要为了写入器那套怪癖（`userCommentForHEIFWriter` 的 BOM 与补 NUL）沿用它的输出：那是喂给
ImageIO 写入器的，这里是自己写字节。

### 3.3 接进照搬

`carryRawExif` 照搬的是「源 TIFF」或「改写过备注的源 TIFF」。之后的闸门、布局、落盘都不变。
自检（`rawExifRegression`）：

- 第 1 条「读回的 TIFF 与源逐字节相同」改成「与**打算照搬的那份**逐字节相同」。
- 第 3 条「视图不退步」不变。它现在对改写过的块应当放行（备注读得出、等于源侧修补后的值）；
  改写后仍然退步的（比如同时还有 EXIF 与 IIM 打架），照旧退回系统重写。

`-v` 那一行说明改写过，例如 `EXIF 整块照搬（831 字节，备注改写成 ImageIO 读得出的写法）`。
字节数报源 TIFF 的。

### 3.4 校验（第 18 轮 4.2 那条要认这种改写）

「Exif 项在文件末尾 ⇒ 照搬过的产物」不变。产物的 TIFF（P）与源的 TIFF（S）的关系，下面两种
之一才算一致，否则照旧报 `变化 EXIF 数据块：…`：

1. P 与 S 逐字节相同。
2. P 是 S 的「备注改写」，全部满足：
   - 源满足 3.1 的改写条件（ImageIO 读不出源的备注、`rawExifUserComment` 解得出 T、ExifIFD 里
     恰好一个 0x9286）。源的备注 ImageIO 本来读得出却被改写了，不算。
   - P 的前 |S| 个字节与 S 相同，只有那一条的 type、count、offset 这 10 个字节可以不同。
   - 那一条在 P 里是 type 7，值恰好占满 S 之后（补齐到偶数之后）到 P 末尾的全部字节；
     补的那个字节是 0。
   - 这段值就是 3.2 对 T 规定的写法（用同一个函数算出来比，或者解出来比文本并核对头部，
     选一种，说明理由）。

`--verify` 照旧不知道转换时走了哪条路，只看两个文件。备注的值本身已经由键空间比对管
（源侧视图是修补后的 T，产物侧是 ImageIO 读回的值）。

`Tests/probe --exif-same` 相应地能说出第三种结果（例如「只差备注改写」）。

## 4. 验收标准

### 4.1 见证（端到端）

1. **`无前缀`（MM，中文）再加上 `读不出的标签` 的那组标签和 `GPS精度`**：默认路径 `-v` 说照搬了
   并改写了备注；`✓ 元数据校验通过`；`--delete-original` 删了源；产物里 ImageIO 读得出备注、
   等于原文；probe 报「只差备注改写」；Exif 项在末尾。`--no-raw-exif`：那组标签的丢失行照旧。
2. **小端（II）**：`test_pic/P1130939.JPG` 的拷贝（它是 II，没有 UserComment），用 `mangle` 加一条
   无前缀的中文备注（`mangle` 做不到就扩展它）。断言同上；另外 `{MakerPanasonic}` 或
   `{ExifAux}` 里挑一个键，产物里读得出且等于源（MakerNote 没被改写碰坏）。
3. **纯 ASCII 的无前缀备注**（MM、II 各一）：同上，产物里的值是 `ASCII\0\0\0` 开头的那种写法
   （probe 或单测核对头部）。
4. **含 BMP 之外字符的备注**（如表情符号）：读回等于原文。
5. **改写了仍退步的**：无前缀备注 + EXIF 与 IIM 打架（`只改IIM` 的配方叠加）：没照搬，产物与
   `--no-raw-exif` 逐字节相同，`-v` 有原因。
6. **不该改写的不改写**：备注有合规头的（`unicode备注`、普通夹具）、没有备注的：`-v` 里没有
   「改写」字样，probe 报「相同」。

### 4.2 单测

改写函数（手搭 TIFF，MM 与 II 各一套）：
- 只动了那 10 个字节，尾部是规定的写法，奇数块长补了一个 0，偶数块长不补；
- ASCII / 非 ASCII / 代理对；值内联的条目（count ≤ 4）；
- 不改写：没有 ExifIFD、没有 0x9286、两个 0x9286、条目越界、ExifIFD 指针越界。

校验规则 3.4（纯函数，喂两段 TIFF 和源侧的条件）：
- 接受：逐字节相同；标准的改写（MM、II、ASCII、非 ASCII）。
- 报出：改写之外另有一个字节不同；尾部文本与 T 不同；尾部写法不是规定的那种（比如无 BOM 的
  UTF-16）；条目指向别处；尾部多一个字节；补齐字节不是 0；源的备注 ImageIO 读得出却被改写；
  type 不是 7。

### 4.3 变异（每条亲眼看红，贴红的那几行）

| 变异 | 必须红在 |
|---|---|
| 不改写（恒照原样照搬） | 4.1 第 1–4 项（被挡回系统重写，丢 MakerNote 等） |
| 改写的文本少一个字符 | 自检挡回 → 4.1 第 1 项红；再去掉「视图不退步」→ 校验的键空间比对报备注变了 |
| 非 ASCII 时不写 BOM | 4.1 第 2 项（II）红；说明 MM 的见证为什么不红 |
| ASCII 文本也走 UNICODE 写法，或反过来 | 4.1 第 3 项 / 4.2 |
| 改写时顺手多改一个别的字节（如块里随便一处） | 4.2；并且端到端由 3.4 报 `变化 EXIF 数据块` |
| 3.4 放宽成「前 |S| 字节相同就行，不管那 10 个字节以外」之类 | 4.2 的「报出」各条 |
| 3.4 去掉「源满足改写条件」 | 4.2「源的备注读得出却被改写」 |
| 自检第 1 条仍与源 TIFF 比（没改成与打算照搬的那份比） | 4.1 第 1 项（改写的全被挡回） |

### 4.4 零噪声

- 测试套件里所有不带无前缀备注的夹具、`test_pic/` 两张：产物与 f1ced2c 逐字节相同，
  `-v --verify` 输出逐行相同。
- `--no-raw-exif`：所有夹具（含带无前缀备注的）产物与 f1ced2c 的 `--no-raw-exif` 逐字节相同。
- 带无前缀备注的夹具，默认路径：产物比 `--no-raw-exif` 的恰好大
  「10 + 源 TIFF 字节数 + 补齐（0 或 1）+ 新值字节数」；`--verify` 的差异行只少不多。

### 4.5 健壮性

对「带无前缀备注的源 JPEG」的 EXIF 段逐字节翻位、逐字节截断走完整转换：不崩，产物打得开；
改写函数对任意字节不崩、不越界。
