  拷二进制出去用之前先确认它是还原之后重编的。

一批代码一个提交（可以分「键的规范化」和「测试」），文档单独一个。全部做完再交报告。

## 1. 现象

批量转换（默认 18 并发）带 `--verify` 时，偶尔有文件被报 `丢失 XMP/photoshop_1_:City = …`
这类行，单独重转又通过。前两轮验收在畸形样本库里各撞上一次。

## 2. 交接方量到的事实（main = 5b7b814）

量具在 [`round-24-repro/`](round-24-repro/)：`ns.swift`（打印一个文件 XMP 里各前缀对应的命名空间）、
`trip.swift`（源与产物的 XMP 按命名空间 URI 比，不看前缀）、`variants.py`（造样本）。只供参考，
测试不得依赖，也不得依赖 Python。

### 2.1 前缀是 ImageIO 临时起的，重名时加 `_N_`

XMP 里一个命名空间由 URI 认，前缀只是文件里的简写。ImageIO 读 XMP 时：

- 标准 URI 一律用它自己的标准前缀：把 `xmlns:photoshop=` 改名成 `xmlns:photoshoq=`（URI 不变），
  读出来仍是 `photoshop:`。
- 文件声明的前缀已经被**别的 URI** 占着时，改叫 `前缀_1_`、`前缀_2_`……例如
  `xmlns:photoshop="http://ns.adobe.com/photoshop/1.1/"`（非标准 URI 用了标准前缀）读成
  `photoshop_1_:City`。

### 2.2 `_N_` 的编号，以及要不要加 `_N_`，取决于同一时刻进程里别的线程在处理什么

`Tests/fixture --rich-xmp` 的样本改出几个变体（`variants.py`），每种 20 份放一个目录，
`--verify -j 18`，每组跑 6 批：

| 一批里有什么 | 结果 |
|---|---|
| 同一种非标准 URI × 20（或混在 40 个正常文件里只有 1 个） | 0 误报 |
| `photoshop` 前缀配两种非标准 URI，各 20 | 每批 5–8 个文件报 `丢失 XMP/photoshop_1_:City` 等 3 行（`-j 1` 时 0） |
| 自定义前缀 `jt` 配两种 URI，各 20 | 每批 6–9 个文件报 `丢失 XMP/jt:Custom` |
| 3 个不同变体混在 30 个正常文件里 | 6 批里出现过 |

第三行说明不只是「标准前缀被占」：两个文件用同一个自定义前缀指不同的 URI（同一家软件的命名
空间换了版本号就是这样），先到的拿到 `jt`，另一个临时叫 `jt_1_`。同一个文件读两次——源读一次、
产物读一次——拿到的前缀可能不同，键就对不上。

机制没有完全查清（推断是 ImageIO 的前缀登记是进程级的，随 XMP 对象的生灭占用和释放），
修法不依赖它。只读不写的多线程探针复现不出来，要走完整转换才出现。

### 2.3 产物是对的

并发 5 批、225 个产物，用 `trip.swift`（单线程、每对一个进程）按命名空间 URI 比源与产物的 XMP：
除 ImageIO 自己的 `iio:hasIIM`（已是易变键）外全部一致。产物的 XMP 里声明的前缀有时是
`photoshop_1_`、`photoshop_1__1_`、`stArea_1_` 这样的名字——前缀叫什么不影响含义。

### 2.4 它还会改变产物

`metadataKeySpace` 同时是整块照搬「视图不退步」自检的尺子。自定义前缀那一组里有一批出现了
`EXIF 没有照搬`（40 张里 1 张）：照搬前后两次读产物拿到的前缀不同，被当成退步，退回了系统重写。
所以这不只是校验多报，偶尔会让一张图白白丢掉整块照搬。

### 2.5 规则里引用到的前缀

`grep 'xmpKey("'`：`dc`、`exif`、`photoshop`、`tiff`、`xmp`、`MicrosoftPhoto`、`iio`。

## 3. 设计（已定）

`xmpTags` 出来的键，前缀改由**命名空间 URI** 决定，不用 ImageIO 临时给的前缀。校验和自检用的是
同一个 `metadataKeySpace`，一处改了两处都好。

### 3.1 规则

对路径里的每一段（嵌套结构的每一层都要处理），按这一段的命名空间 URI 取前缀：

1. **URI 在标准表里** → 用表里的标准前缀。表至少包含 ImageIO 公开的十个命名空间
   （`kCGImageMetadataNamespace*` 与对应的 `kCGImageMetadataPrefix*`：Exif、ExifAux、ExifEX、
   DublinCore、IPTCCore、IPTCExtension、Photoshop、TIFF、XMPBasic、XMPRights），加上规则里引用到
   而不在其中的（2.5：`MicrosoftPhoto`、`iio`；用 `ns.swift` 量出它们的 URI）。
   **规则里引用到的每个前缀都必须在表里**，否则那条规则认的就是「恰好叫这个名字的任何命名空间」。
2. **不在表里** → 取 ImageIO 给的前缀，去掉末尾所有的 `_数字_`（可能叠了几层），得到「基名」：
   - 基名是表里某个标准前缀（非标准 URI 借用了标准前缀）→ 键里带上 URI，例如
     `XMP/photoshop{http://ns.adobe.com/photoshop/1.1/}:City`。它与真正的 `photoshop:City` 是
     两个键，规则不会把它当成标准字段。
   - 同一个文件里有不止一个不在表里的 URI 落到同一个基名 → 这几个都带上 URI。
   - 否则 → 就用基名，键和现在一样（`XMP/jt:Custom`、`XMP/lr:hierarchicalSubject[0]`）。

带 URI 的写法（上面用 `{…}` 只是示意）你定，要求：

- 单射：不同的 URI 不能写成同一个键。URI 里的控制字符、非 ASCII 字节、以及会和键的语法撞车的
  字符要转义（畸形样本里的 URI 含 0xFF 和换行）。
- 不能把现有的键处理函数搞糊涂：`strippingAllArrayIndices`、`carrierValues`、
  `ReconciledGroup(viewKey:)`、`isVolatile` / `isIgnoredKey`、`makerNoteGroup` 等对这种键要照常
  工作（URI 里有 `/`、`.`、`:`、`[`、`]` 的都要测）。
- 差异行里直接显示这个键，人看得懂是哪个命名空间。

每一段的 URI 从哪来：递归枚举时每个标签都给得出自己的前缀和命名空间
（`CGImageMetadataTagCopyPrefix` / `CopyNamespace`），先扫一遍建好这份文件的「前缀 → URI」表，
再改写路径。路径里出现表里没有的前缀时原样保留。

### 3.2 不变的

- 正常文件（所有命名空间要么标准、要么各用各的前缀）的键与现在逐字节相同：校验输出、
  `Tests/probe` 的键、现有断言都不该变。
- 不去控制产物 XMP 里声明的前缀叫什么（那是 ImageIO 序列化时定的，2.3）。
- 不给转换加锁、不降并发。

## 4. 验收标准

### 4.1 单测（纯函数：一组「路径 + 值」和「前缀 → URI」表进，键出）

- 标准命名空间：键不变；标准 URI 配了别的前缀（`photoshoq`）→ 标准前缀。
- 自定义前缀：`jt` 与 `jt_1_`、`jt_2_`、`jt_1__1_` 配同一个 URI → 同一个键 `XMP/jt:…`。
- 非标准 URI 借用标准前缀：`photoshop_1_`、`photoshop_2_`、`photoshop_1__1_` 配同一个 URI →
  同一个带 URI 的键；配不同 URI → 不同的键；都不等于 `XMP/photoshop:…`。
- 同一文件里两个不在表里的 URI 同基名 → 都带 URI，互不相同。
- 嵌套路径（`mwg-rs:Regions.mwg-rs:RegionList[0].mwg-rs:Area.stArea:x` 这种，其中一层的前缀被
  改名）、带数组下标、带语言下标（`[x-default]`）。
- URI 含 `/ . : [ ] { }`、空格、控制字符、0xFF、换行：单射，键处理函数照常工作。
- 表：规则里引用到的每个前缀都在表里（列出来逐个断言它的 URI）。
- 键空间比对：源是 `jt:`、产物是 `jt_1_:`（同 URI）→ 无差异；源是 `photoshop_1_:`、产物是
  `photoshop_2_:`（同 URI）→ 无差异；URI 不同 → 报丢失。

### 4.2 端到端（`Tests/selftest.sh`，样本用 `mangle` 造，需要就扩展它）

1. **并发见证**：`photoshop` 前缀配两种非标准 URI、`jt` 前缀配两种 URI，四种各 10 份（或你量出
   更稳的组合），`-v --verify -j 18` 跑 3 批：每一批每一张都 `✓ 元数据校验通过`，每一张都
   `EXIF 整块照搬`。修之前这样一批几乎必然有 5 张以上报丢失（交接方 20 多批里没有一批是干净的）
   ——你先在没改的代码上亲眼确认它红，再改。
2. **确定性的见证**（不靠并发）：非标准 URI 借用标准前缀的那张，单独转：校验通过；
   用 `probe` 读源的键是带 URI 的那种写法，产物上同一个键读得出同值。把产物的 XMP 删掉一个这样的
   标签做不到的话，至少断言「把 URI 换成另一个的样本，当作产物去比」会报丢失（单测也行）。
3. **真丢了照报**：`--lossy` 之类现有的 XMP 丢失断言不变。

  相同，`-v --verify` 输出逐行相同。

### 4.5 健壮性

规范化对任意前缀、URI、路径不崩（空串、超长、全是 `_1_`、路径里的前缀不在表里）。
