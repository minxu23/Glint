# 第 22 轮交接稿：扩展属性进校验、AROT 不报、把「照片」的说明写进文件

工作规则、长期要求、变异与 mtime 陷阱的注意事项，全部沿用
[`round-12-handoff.md`](round-12-handoff.md) 的第 0 节，先读那一节。另加：

- 变异后用 `cp` 从快照还原要 `touch` 源文件，并确认那次 `make test` 的输出里有 swiftc 那行；
  拷二进制出去用之前先确认它是还原之后重编的。
- 逐字节比较产物时不要并行跑别的转换。大批量的临时产物用完就删。

三件互不相干的事，分三批：**A 校验核对扩展属性 → B AROT → C 写说明的选项**，一批一提交
（文档跟着各批一起改，或最后单独一个提交）。全部做完再交报告。

## 背景

用户给了一张真实的带备注的 iPhone 照片（不在仓库里，你拿不到）。量下来：**备注不在图像文件里**，
是「照片」App 的说明，存在文件的扩展属性 `com.apple.assetsd.description` 里（UTF-8 文本）；
同一张照片上还有 28 个 `com.apple.assetsd.*` 属性（评分、收藏、原始文件名、位置等）。

## A. 校验核对扩展属性

### 量到的事实（main = 1626905）

- 转换时 `copyExtendedAttributes` 把源的扩展属性逐个拷到产物，只跳过 `skippedXattrs`
  （`com.apple.quarantine`、`com.apple.ResourceFork`）。实测：那张真实照片 29 个属性在产物上
  全部同名同值；另造一张带 11 个属性的样本（`assetsd.description`、访达备注
  `com.apple.metadata:kMDItemFinderComment`、访达标签 `_kMDItemUserTags`、`kMDItemWhereFroms`、
  `FinderInfo`、`lastuseddate#PS`、`macl`、`provenance`、`user.custom`、隔离标记、资源分支），
  产物上除被跳过的两个以外 9 个同名同值。
- **`--verify` 完全不看扩展属性**：把产物上的 `com.apple.assetsd.description` 删掉再跑
  `metadataDiff`，结果是 0 处差异。拷贝失败（`setxattr` 返回非 0 时现在只是不计数）、或目标
  文件系统不存扩展属性时，校验通过，`--delete-original` 会删源，备注就没了。

### 要做的

`metadataDiff` 加一条：源上的每一个扩展属性，除了转换时本来就不拷的那几个（和拷贝用**同一份**
`skippedXattrs`，不要另写一份清单），产物上必须有同名的、值逐字节相同的一份。

- 产物上没有：`丢失 扩展属性 <名字>（N 字节）`
- 值不同：`变化 扩展属性 <名字>（N 字节 → M 字节）`；等长时注明从第几个字节起不同。
- 这三种给出人看得懂的名字，并把值显示出来（截断规则沿用 `truncate`）：
  - `com.apple.assetsd.description`：`「照片」的说明`，值是 UTF-8 文本；
  - `com.apple.metadata:kMDItemFinderComment`：`访达备注`，值是二进制 plist 里的一个字符串
    （解不出就只报字节数）；
  - `com.apple.metadata:_kMDItemUserTags`：`访达标签`，值是二进制 plist 里的字符串数组。
  例如 `丢失 「照片」的说明（扩展属性 com.apple.assetsd.description）= 西湖日落…`。
- 产物上多出来的属性不报。
- 源或产物的属性列表读不出（`listxattr` 出错）时报一行「无法核对扩展属性」，不当作没有差异。
- 如果量到某个系统属性在转换后**本来就会**与源不同（系统自己改写的），不要悄悄放过：先确认
  现象可复现，再把它列为不比的，写明依据，并写进报告。交接方没有量到这样的属性。

### 验收

1. **端到端**：夹具加上 `assetsd.description`、访达备注、访达标签、一个自定义属性
   （`xattr` 命令或 `fixture` 现有的做法）。转换后：产物上四个都在、值相同；
   `✓ 元数据校验通过`；`--delete-original` 删源。带隔离标记的源：产物上没有隔离标记，校验不报。
2. **单测**（对真实文件：转一张，再动产物的属性，调用 `metadataDiff`）：删掉一个 → 报丢失；
   改一个字节 → 报变化；改长度 → 报变化；删掉说明 → 报的那一行带着说明的文本；
   产物多一个属性 → 不报；被跳过的两个属性源上有、产物上没有 → 不报。
   纯函数部分（两边的「名字 → 值」字典进，差异行出）单独测，含三种带名字的显示和 plist 解不出的情形。
3. **变异**（每条亲眼看红）：
   - 转换时不拷扩展属性 → 第 1 项红在「校验通过」（说明校验端到端看得见），也红在「产物上有」；
   - 校验里这一条去掉 → 上一条变异下「校验通过」变回绿，只剩「产物上有」红；单测全红；
   - 校验用另一份跳过清单（比如把 `assetsd.description` 也跳过）→ 单测红；
   - 只比名字不比值 → 单测「改一个字节」红。
4. **零噪声**：测试套件里所有夹具、`test_pic/` 两张，两条路的 `--verify` 输出与 1626905
   逐行相同，产物逐字节相同（这一批不改转换）。

## B. `AROT` 段不报

### 量到的事实

那张真实照片转成的 JPEG（5712×4284，ImageIO 在 Apple 芯片上写的）里有一个 APP10 段，内容以
`AROT\0\0` 开头，1084 字节。现在校验报 `丢失 APP10 段（AROT，1084 字节）`。量到的：

- 条目数（按 4 字节一条）269，图像的 MCU 行数（高 ÷ 16）是 268；同一个文件里 `DRI` 的重启间隔
  是 357，正好是一行的 MCU 数（宽 ÷ 16）。
- 有没有增益图它都在（不带增益图重新写一份，同样的段长）。
- 3456×2304 和 1600×1200 的图用 `sips` 转出来没有它。
- exiftool 把它叫 `HDRGainCurve`，但它与增益图无关（上一条）。

结论：它是这份 JPEG 压缩数据的逐行索引（配合每行一个重启标记，供快速解码或旋转），只对这份
JPEG 的码流有意义，转成 HEIF 后不该存在。用户已决定不报。

### 要做的

APP10 段、内容以 `AROT\0\0` 开头的，归入不报的结构性数据（与现有的结构性段同一处、同一种
写法，注释里写上面的依据）。别的 APP10 段（包括以 `AROT` 开头但后面不是两个 0 的）照旧报。

### 验收

- 端到端：`mangle --segment` 造一个 `AROT\0\0` 开头的 APP10 → 校验不报这一段；造一个别的内容的
  APP10 → 照旧报。
- 变异：去掉这条 → 第一条红。
- README「`--verify` 到底比什么」里列不报的段的地方加上它和依据。

## C. 选项：把「照片」的说明写进文件

### 为什么

扩展属性离开 macOS 很容易丢（非苹果文件系统、网盘、发到别的设备）。用户要一个选项，把说明
同时写进图像文件内部。

### 量到的事实（探针见 `round-22-repro/embed.swift`）

- 第二遍（`CGImageDestinationCopyImageSource` 合并 XMP）时，在要合并的 `CGImageMetadata` 上
  `CGImageMetadataSetValueMatchingImageProperty(md, kCGImagePropertyIPTCDictionary,
  kCGImagePropertyIPTCCaptionAbstract, 文本)`，产物的 XMP 里就有 `dc:description`。
  ImageIO 读产物：`{IPTC}/Caption/Abstract` 和 `{TIFF}/ImageDescription` 都是这段文本；
  exiftool 读到 `XMP-dc:Description`。
- 之后再做 EXIF 整块照搬：上面两种读法都不变，`源 → 产物` 的校验 0 处差异（产物里多出来的键
  不报）。EXIF 块本身没有被动过。
- **源里已经有说明时（`dc:description` 是多语言数组）再这样写，`CopyImageSource` 里抛 ObjC 异常，
  进程直接崩**（`-[__StringStorage count]: unrecognized selector`）。Swift 接不住这种异常。
- 源里没有 XMP 时现在不做第二遍；要写说明就得自己建一份 `CGImageMetadata` 做第二遍。

### 要做的

命令行加 `--embed-caption`（名字可以调整，帮助里写清楚：把「照片」App 的说明写进 HEIF 的 XMP
说明字段，让它离开 Mac 也跟着文件走）。默认关；图形界面不加。

开了之后，每张图：

1. 取源文件的 `com.apple.assetsd.description`。没有、为空（去掉首尾空白后）、或不是合法 UTF-8：
   不写。
2. 源的元数据里已经有说明——`XMP/dc:description`（任何语言）、`{IPTC}/Caption/Abstract`、
   `{TIFF}/ImageDescription` 三者有任何一个非空：**不写**（不覆盖、不追加；这也避开上面的崩溃）。
   已有的说明与扩展属性里的相同也一样不写。
3. 否则写进产物 XMP 的 `dc:description`。只动 XMP，不往 EXIF 里写任何东西。
4. 写完读回核对：产物的 ImageIO 视图里 `XMP/dc:description`（x-default）等于那段文本。不等或
   没有：当作没写成。
5. 扩展属性里的那一份照旧拷到产物上（A 批照旧核对它）。

让人看得见：

- `-v` 多一行：写了（多少个字符），或没写及原因（没有说明 / 文件里已有说明 / 不是合法的 UTF-8 /
  没写成）。没开选项时不出这一行。
- 开了选项、该写而**没写成**（第 4 步不过）时，不能静默：`--verify` 的结果里加一条差异
  （措辞你定，例如 `没能把「照片」的说明写进文件`），`--delete-original` 因此不删源。
- 没开选项时，产物与 1626905 逐字节相同。

与现有机制的关系：

- 整块照搬的「视图不退步」自检：写进去的键在照搬前后的产物里都有、源里没有，不构成退步——
  确认照搬照常发生，没有因此被挡回。
- 校验：产物比源多出 `XMP/dc:description`、`{IPTC}/Caption/Abstract`、`{TIFF}/ImageDescription`，
  现有规则不报多出来的键——确认零噪声。

### 验收

1. **端到端**（`fixture --no-text` 没有任何文本字段，给它加上 `assetsd.description`）：
   - 不带选项：产物里没有 `dc:description`；产物与 1626905 逐字节相同。
   - 带选项：`probe` 读产物的 `XMP/dc:description[x-default]` 等于说明；`{IPTC}/Caption/Abstract`
     也等于它；校验通过；`-v` 说写了；扩展属性还在；EXIF 整块照搬照常（`-v` 里那一行还在，
     `--exif-same` 的结果与不带选项时相同）。
   - 中文、带换行、带 emoji、很长（几千字）的说明各一张。
2. **已有说明不写**：普通夹具（有 `dc:description`、IPTC 说明、ImageDescription）加上扩展属性、
   带选项：**不崩**，产物里的三个字段与不带选项时相同，`-v` 说明原因。三个字段只有其中一个时
   （各造一张）也不写。
3. **不写的其它情形**：没有这个扩展属性；值是空白；值不是合法 UTF-8。
4. **没有 XMP 的源**（比如 `test_pic` 的拷贝去掉 XMP 段，或现有的无 XMP 夹具）加上扩展属性、
   带选项：写得进去。
5. **没写成时不静默**（单测：给转换注入一个「第二遍不带说明」的编码步骤，沿用第 19 轮留的
   `encode` 接缝）：`--verify` 的结果里有那一条，转换算成功，`-v` 说没写成。
6. **变异**（每条亲眼看红）：
   - 不看第 2 步（已有说明也写）→ 第 2 项红（崩溃也算红，但要看到是这一条）；
   - 不带选项也写 → 第 1 项「不带选项」红；
   - 第 4 步的读回核对去掉 → 第 5 项红；
   - 写进去的文本截掉一个字符 → 第 1 项红；
   - 往 EXIF 的 ImageDescription 也写一份（破坏整块照搬）→ 第 1 项 `--exif-same` 那条红。
7. **零噪声**：不带选项时，所有夹具、`test_pic/` 两张，产物与输出和 1626905 相同（A 批的
   校验新增行除外，那些样本本来就没有）。

## 不做的

- 不把访达备注、别的 `assetsd.*` 属性写进文件。
- 不改 EXIF 整块照搬、备注（UserComment）相关的任何逻辑。
- 不给图形界面加开关。
